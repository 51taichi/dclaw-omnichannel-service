# 群定时任务响应式布局修复设计

## 目标

修复群管理右侧配置区在中等宽度下裁切群定时任务操作按钮的问题，并保证任务名、@ 角色姓名及执行记录标题不会因文字长度破坏布局。保留现有卡片、SVG icon、状态胶囊和按钮风格。

## 根因

任务卡使用三列最小宽度 `220px + 155px + 280px`，响应式切换却依赖页面宽度 `900px`。群管理同时存在 300px Bot 侧栏和 30/70 群工作台，因此页面仍宽于 900px 时，右侧任务卡容器可能已不足 700px。父容器设置 `overflow-x: hidden`，最终把右侧操作按钮裁掉。

## 方案

在群定时任务区域启用 inline-size 容器查询：

- 容器宽度充足时保持“任务信息 / 状态与倒计时 / 操作”三列卡片。
- 容器进入中等宽度时改为“任务信息 / 状态”两列，操作按钮独占下一行并允许换行。
- 容器较窄时改为单列，标题、状态和操作自然纵向排列。
- 页面级媒体查询继续负责群管理整体的移动端结构；任务卡自身不再依赖页面宽度判断可用空间。

补充文字约束：

- @ 角色卡片中的成员姓名使用单行省略，身份说明保持现有省略行为。
- 执行记录首行允许标题区域收缩，标题单行省略；窄容器下首行可换行，状态标签保持完整。

## 验证

- 新增 CSS 回归测试，要求存在任务区容器查询、两列/单列切换及两处长文本保护。
- 先运行测试确认因规则缺失失败，再实施最小 CSS 修改。
- 运行群定时任务相关测试与全量测试。
- 使用真实控制台宽度结构，在 1440px、1280px、900px 和 700px 视口检查卡片 `scrollWidth <= clientWidth`，并确认按钮、标题和状态均可见。

## 非目标

- 不改变定时任务业务状态、接口、按钮顺序或操作方式。
- 不把操作按钮收进更多菜单。
- 不调整群管理其他功能的视觉设计。
