# 连续客户消息合并设计

## 目标

当同一客户或同一群聊在短时间内连续发送多条文本消息时，控制台服务端先短暂收集，再将这些消息作为一个完整问题调用一次 DClaw Agent，使客户收到一条上下文完整的回复。

本功能只改变 Agent 调用的触发粒度，不合并或删除原始会话记录，也不改变 WorkTool 回调协议。

## 核心规则

- 归并键为 `botId + conversationKey`。不同 Bot、不同私聊、不同群聊完全隔离。
- 第一条可处理文本消息到达后进入缓冲，不立即调用 Agent。
- 每收到一条同会话的新文本消息，将静默等待时间重新计算为最后一条消息后的 10 秒。
- 从第一条消息开始最多等待 15 秒。达到上限后，即使客户仍在继续输入，也立即截取当前批次调用 Agent；后续消息进入下一批。
- 默认配置：静默窗口 10 秒，最大窗口 15 秒。
- 两个时间通过环境变量维护，便于后续按真实响应体验调整。

建议环境变量：

```env
INBOUND_COALESCE_QUIET_MS=10000
INBOUND_COALESCE_MAX_MS=15000
```

## 数据流

1. WorkTool 回调到达后，服务端立即完成鉴权、幂等判断和原始消息入库。
2. 好友添加、非文本事件、调试 `ping/pong` 等特殊事件继续沿用现有即时处理逻辑。
3. 符合 Agent 处理条件的文本消息进入对应会话缓冲。
4. 缓冲窗口关闭时，服务端按回调到达顺序读取本批消息。
5. 单条消息保持原有文本；多条消息构造成明确的连续消息结构，例如：

```text
客户连续发送了以下消息，请结合上下文统一回答：
1. 去哪里听？
2. 收钱的不？
```

6. 服务端基于最后一条消息的会话身份、群聊信息和回复目标构造一次 Agent 请求。
7. Agent 返回后只发送一次完整回复，并按现有规则处理文本拆分、附件、来源和发送回调。

## 会话与业务规则

- 每条客户原始消息仍分别写入 `incoming_messages` 和会话消息表，控制台显示不丢失、不拼成一条。
- Agent 调用记录只创建一次，并记录本批次包含的消息数量和消息标识，便于排查。
- 状态机上下文、标签规则和客户资产基于完整合并内容判断一次。
- 客户任何一条有效私聊消息到达时，立即取消旧的客户激活任务；归并完成并成功回复后，再按当前节点重新启动计时。
- 状态机节点推进、标签变化和激活任务调度只执行一次，避免连续消息造成重复推进。
- 群聊仍遵守现有规则：只有符合 `@` 条件的消息进入 Agent。一个批次中至少有一条有效 `@` 消息时，才允许形成回复批次。
- 人工接管中的消息不触发 AI 回复，继续按现有逻辑同步到 Agent；不进入 AI 消息缓冲。

## 并发与顺序

- 每个会话同时最多存在一个待归并批次。
- 同一会话若上一批已经开始调用 Agent，新消息不能混入已经发出的请求，而是进入下一批，确保数据不会被并发修改。
- 同一会话的批次必须串行执行，防止后到批次先回复。
- 不同会话可以独立等待；最终 Agent 调用仍服从当前全局 Agent 队列，避免破坏已有发送稳定性。
- 第一版使用进程内缓冲，适用于当前单容器实例。未来多实例部署时，将缓冲状态和定时任务迁移到 Redis/BullMQ，接口语义保持不变。

## 重启与异常处理

- 原始消息先入库，因此进程异常不会丢失聊天记录。
- 第一版进程重启时，尚未关闭的内存批次不会自动恢复调用；日志必须记录缓冲创建、追加、关闭和丢弃事件。
- Agent 调用失败沿用当前重试和私聊失败兜底规则，不重复创建同一批次。
- WorkTool 重复回调仍先经过现有 `messageKey` 幂等机制，不会因为归并而重复计数。
- 清空会话、切换人工接管、删除 Bot 或重新绑定 Agent 时，必须取消该会话未执行的缓冲批次。

## 可观测性

新增结构化日志事件：

- `incoming.coalesce.started`：创建批次。
- `incoming.coalesce.appended`：追加消息。
- `incoming.coalesce.flushed`：窗口关闭并开始处理。
- `incoming.coalesce.canceled`：因清空、人工接管、绑定变化等原因取消。

日志至少包含 `botId`、`conversationKey`、批次 ID、消息数量、等待时长和关闭原因（`quiet_window` 或 `max_window`）。Agent 调用日志同时记录批次 ID，便于串联整条链路。

## 测试边界

- 同一私聊在 10 秒内连续两条消息只调用一次 Agent，并保留两条入库记录。
- 第二条消息到达后静默窗口重新计时。
- 连续输入超过 15 秒时按最大窗口截断，不会无限等待。
- 不同会话的消息不会互相合并。
- 同一客户在不同 Bot 下不会合并。
- 重复 WorkTool 回调不会进入批次两次。
- 群聊未 `@` 消息不会错误触发；有效 `@` 连续消息可合并。
- 人工接管、清空会话和 Agent 换绑会取消待处理批次。
- 状态机、标签和激活逻辑对一个批次只执行一次。
- 单条消息也会经过最多 10 秒静默窗口，并保持原有 Agent 请求语义。

## 验收标准

客户在 9 秒内连续发送“去哪里听？”和“收钱的不？”时，会话页保留两条客户消息；服务端只产生一次 Agent 调用，机器人用一条回复同时回答地点、参与方式和是否收费，且不会重复推进任务状态或重复安排激活。
