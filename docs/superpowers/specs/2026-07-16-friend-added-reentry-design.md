# 新增好友再次进入流程设计

## 目标

WorkTool 的 `textType=22`、`type=105` 新增好友回调在首次发生时创建入口节点激活；同一客户在超过冷却期后再次触发该回调时，重新进入入口节点并重新启动入口节点的第一条激活话术。

## 规则

- 以 `botId + friendName` 生成既有私聊会话键。
- 十分钟内的重复新增好友回调视为 WorkTool 重试，只记录 `friend_added.skipped`，原因是 `friend_added_cooldown`。
- 超过十分钟后收到新增好友回调，保留聊天原文和已收集资产，重置当前节点为状态机入口节点、恢复 AI 接待、清空激活进度、取消旧激活任务。入口节点启用激活且有话术时，再启动第一条激活话术；未配置话术时仍完成流程重入。
- 新增好友路径不调用 DClaw，不额外发送欢迎语。
- 群聊不参与该逻辑。

## 数据与可靠性

`flow_sessions.last_friend_added_at` 持久保存最近一次有效新增好友回调时间。数据库中的单一事务同时完成冷却判断、旧任务取消、流程重入、时间戳写入和首条激活任务创建，避免并发回调重复创建任务或在崩溃后留下无任务的冷却窗口。

## 测试

- 首次新增好友创建入口激活。
- 冷却期内回调不改变节点、不产生新任务。
- 冷却期后回调重置节点与 AI 接待，但保留资产。
- 流程重入取消旧任务并让后续调度使用新的 generation。
