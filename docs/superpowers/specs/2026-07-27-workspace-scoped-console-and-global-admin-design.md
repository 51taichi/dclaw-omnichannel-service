# 工作区控制台与全局管理员后台设计

## 背景

当前 `/console/` 会展示系统中的所有 Bot。随着不同公司、部门和组织共同使用同一套服务，员工需要通过不同 URL 只看到自己负责范围内的 Bot。同时，Agent 管理属于系统级能力，不应继续放在某个 Bot 的配置页中。

本次新增“工作区”和独立的全局管理员后台，但不改变现有 Bot 的业务逻辑、Bot 独立密码、角色权限、会话、任务、标签、推送、日志、回调或 worker 行为。

## 目标

- 每个工作区拥有管理员自定义的唯一 URL。
- 工作区 URL 只展示分配给该工作区的 Bot。
- 员工通过轻量、有趣的“对口令”进入工作区。
- Bot 仍需使用现有 Bot 密码或全局管理员密码解锁。
- 新增独立 `/admin/`，集中维护工作区、Bot、Agent 和系统设置。
- 全局管理员始终只有一个，不增加管理员账号体系。
- 复用当前中台视觉语言和交互习惯。
- 测试环境验证通过后可直接在夜间升级，不保留旧 `/console/` 兼容入口。

## 非目标

- 不把工作区作为新的业务数据租户边界。
- 不改变任何现有 Bot 功能或权限。
- 不改变 `/api/public/bots` 的公开行为。
- 不建立多个管理员账号、角色或管理员列表。
- 不把工作区口令设计成高安全等级认证。
- 不迁移、删除或复制 Bot 的现有业务数据。

## 核心边界

系统分为三个互不替代的层级：

```text
全局管理员
  管理工作区、全局 Bot 清单、Agent 和系统设置

工作区
  决定某个 URL 展示哪些 Bot

Bot
  继续作为业务数据和业务权限边界
```

- 一个 Bot 最多属于一个工作区。
- 一个工作区可以包含多个 Bot。
- 工作区口令只允许读取该工作区的 Bot 列表，不授予任何 Bot 业务权限。
- Bot 仍以 `bot_id` 隔离会话、任务、标签、推送和日志。
- Bot 的 `bot`、`admin` 角色含义保持不变。
- 全局管理员仍可使用全局管理员密码解锁任意 Bot，并取得现有 `role=admin` 权限。
- 普通 Bot 密码解锁后仍不可见配置 Tab。
- 全局管理员解锁 Bot 后仍可见并编辑该 Bot 的配置。

## URL 设计

```text
/admin/          全局管理员后台
/console/:slug   工作区控制台
/console/        重定向到 /admin/
```

工作区 `slug` 由管理员设置：

- 长度为 3 至 32 个字符。
- 只允许小写英文字母、数字和连字符。
- 不允许中文、空格和斜杠。
- `admin`、`api`、`assets`、`public` 等系统保留值不可使用。
- 全局唯一。

修改 slug 后：

- 旧 URL 立即失效。
- 已签发的工作区会话立即失效。
- 员工必须通过新 URL 重新对口令。

未知 slug 展示带品牌的不存在页面；停用工作区展示“当前入口暂不可用”，不能进入 Bot 列表。

## 数据模型

### workspaces

```text
id
name
slug
challenge_text
response_hash
auth_version
enabled
created_at
updated_at
```

- `name` 是管理员配置的展示名称。
- 员工页面只展示名称，不出现“部门”“组织”或“工作区”等固定组织概念。
- `challenge_text` 保存上半句口令明文，用于页面展示。
- 下半句只保存安全 hash，不保存明文。
- `auth_version` 在 slug、上半句或下半句变化时递增，用于批量失效旧会话。

### workspace_bots

```text
workspace_id
bot_id
assigned_at
```

- `bot_id` 建立唯一约束，保证一个 Bot 只能属于一个工作区。
- 移除关系只解除分配，不删除 Bot。
- 删除工作区时解除全部分配，不删除 Bot 或任何业务数据。

### workspace_sessions

```text
token_hash
workspace_id
auth_version
expires_at
created_at
```

- 工作区会话固定有效 30 天，不滚动续期。
- 浏览器只保存随机 token，数据库只保存 token hash。
- 校验时同时检查工作区状态、过期时间和 `auth_version`。
- 修改 slug 或任一口令内容后，旧 token 即使未过期也无法继续使用。

### global_admin_credential

系统只维护一行全局管理员凭据：

```text
username = admin
password_hash
updated_at
```

- 不提供新增、删除或维护多个管理员的能力。
- 管理员登录 token 使用当前服务端内存会话，固定有效 8 小时。
- 服务重启或主动退出后需要重新登录。

## 全局管理员密码迁移

首次升级时：

1. 如果数据库尚无全局管理员凭据，读取当前 `.env` 中的管理员密码。
2. 将密码 hash 写入数据库。
3. 初始化成功后，管理员登录和现有 `x-api-key` 校验均以数据库 hash 为准。
4. `.env` 中的旧密码不再参与后续登录。

管理员可以在 `/admin/` 的系统设置中修改密码。修改后：

- 已有管理员页面会话立即失效。
- 新密码可继续用于现有 Bot 的管理员解锁。
- 新密码可继续作为现有管理员 API 的 `x-api-key`。

服务器提供唯一恢复方式：

```bash
npm run admin:reset-password
```

该命令在服务器终端交互式读取新密码、更新数据库 hash，并使现有管理员会话失效。网页端不提供找回密码功能。

如果迁移失败：

- 禁止全局管理员写操作并记录明确错误。
- 不影响 WorkTool 回调、Agent 调用、激活任务、标签任务、推送任务和其他 worker。

## 工作区对口令流程

1. 员工打开 `/console/:slug`。
2. 服务返回工作区展示名称和上半句口令。
3. 浏览器没有有效工作区会话时，显示对口令登录页。
4. 员工输入下半句并提交。
5. 校验成功后签发 30 天工作区会话。
6. 页面显示 3 秒成功倒计时，结束后进入控制台。
7. 控制台只加载当前工作区分配的 Bot。
8. Bot 保持锁定，员工仍需输入现有 Bot 密码才能操作。

工作区页面提供简洁的退出图标。退出只清除工作区会话，不改动 Bot 数据。

管理员持有有效的 8 小时管理员会话时，可以从 `/admin/` 点击“打开工作区”直接进入，不再要求对口令。该行为不自动解锁工作区内的 Bot。

## 登录页面视觉与状态

工作区对口令页和管理员登录页使用同一套可复用登录壳层，复用中台现有色彩、边框、按钮、输入框和品牌头部。

### 品牌 Logo

使用现有资源：

```text
public/console/assets/deepmega-dclaw-logo.png
```

- Logo 放在登录容器上方的品牌区，不作为全屏背景。
- 桌面端显示宽度限制在 `240px` 至 `300px`，高度按原比例自动计算。
- 移动端显示宽度限制在 `190px` 至 `230px`。
- 使用 `max-width: 100%`，保证窄屏不溢出。
- Logo 与表单保持清晰间距，不与右下角吉祥物重叠。

### 吉祥物资源

实现阶段从以下原图生成三张网页透明 PNG 派生资源：

```text
初始状态：
/Users/moxi/Desktop/codex space/Q/微信图片_20260604143805_28_112.jpg

失败状态：
/Users/moxi/Desktop/codex space/Q/微信图片_20260604143828_29_112.jpg

成功状态：
/Users/moxi/Desktop/codex space/Q/微信图片_20260604144300_39_112.jpg
```

处理要求：

- 初始图去除背景，保留疑惑表情和问号。
- 失败图去除背景、DClaw Logo 和“不干了...”文字，保留生气吉祥物和损坏的电脑。
- 成功图去除背景，保留开心挥手姿态。
- 输出为优化后的透明 PNG，不直接把高分辨率原图加载到页面。
- 保留自然边缘和阴影，不留下白边或原背景残块。

尺寸规则：

- 桌面端吉祥物固定在登录容器右下角，宽度上限 `220px`，且不超过容器宽度的 `34%`。
- 失败图因横向构图较宽，显示盒宽度上限 `250px`，主体视觉高度与另外两张接近。
- 移动端宽度为 `112px` 至 `140px`，移动到表单内容下方靠右。
- 表单内容区为吉祥物预留安全空间，任何断点下都不能遮挡输入框、错误提示、倒计时或提交按钮。
- 使用稳定的图片容器尺寸，状态切换不能造成对话框跳动。

### 三种状态

```text
等待输入
  显示疑惑吉祥物

校验失败
  显示生气吉祥物
  表单内显示简短错误提示
  用户修改输入后可以立即重试

校验成功
  显示开心吉祥物
  显示“验证成功，3 秒后进入”
  每秒更新倒计时
  3 秒结束后进入目标页面
```

成功倒计时期间：

- 禁用输入框和提交按钮。
- 不再发起重复登录请求。
- 不显示额外成功弹窗。
- 页面刷新时以已经签发的有效会话直接进入，不重复播放倒计时。

### 管理员登录复用

`/admin/` 未登录时使用相同视觉结构和三种状态：

- 页面显示同一个中台 Logo。
- 账号固定为 `admin`，以只读账号项展示。
- 主要输入项为管理员密码。
- 初始、失败、成功分别使用同一组三张吉祥物资源。
- 登录成功后同样显示 3 秒倒计时，再进入管理员后台。

## 管理员后台信息架构

```text
[工作区] [Bots] [Agents] [系统设置] [退出]
```

管理员后台复用现有中台布局、导航、表单、按钮、卡片、间距和图标系统，但作为独立 `/admin/` 前端，不把大量管理员条件分支继续塞入现有控制台单页。

### 工作区

左侧：

- 工作区列表。
- 启用状态。
- 新增工作区。

右侧：

- 名称。
- slug。
- 上半句口令。
- 设置或更换下半句口令。
- 启用开关。
- 已分配 Bot 列表。
- 保存、打开工作区、删除工作区。

“分配 Bot”使用模态框：

- 只显示当前未分配的 Bot。
- 支持名称搜索。
- 支持多选。
- 一次确认完成分配。
- 不使用拖拽分配。

已分配 Bot 提供：

- 转移到其他工作区。
- 从当前工作区移除。

转移前明确展示：

```text
原工作区 -> 新工作区
```

并进行二次确认。移除只解除分配。删除工作区前展示受影响 Bot 数量，并说明 Bot 和业务数据不会删除。

### Bots

展示全局 Bot 清单，包含：

- Bot 基础信息。
- 当前 Agent 绑定。
- 当前所属工作区。
- 创建 Bot。
- 分配或转移工作区。
- 进入现有 Bot 配置。

Bot 配置的字段、保存逻辑和权限保持现状。Agent 本身的维护入口不再放在某个 Bot 的配置 Tab 中。

### Agents

把现有 Agent 管理功能移动到全局管理员后台：

- Agent 列表。
- 新增、修改和启停。
- 当前已有字段和 API 语义保持不变。
- Bot 绑定 Agent 的能力仍保留在 Bot 配置中。

### 系统设置

第一版只包含全局管理员密码修改，并为未来真正与某个 Bot 无关的系统配置保留扩展位置。

## 员工控制台

工作区验证完成后，继续使用现有控制台主体：

- 顶部和业务 Tab 保持现状。
- Bot 卡片、Bot 解锁、会话、任务、标签、推送和日志保持现状。
- 页面仅将 Bot 数据源替换为当前工作区 Bot 列表。
- 员工界面展示管理员配置的名称，但不显示“工作区”“部门”或“组织”等系统术语。
- 切换工作区不是页面内功能，进入不同工作区必须使用对应 URL。

`/api/public/bots` 保持现有行为，不收紧、不删除、不改变返回语义。工作区过滤使用独立接口实现。

## API 设计

### 管理员认证

```text
POST /api/admin/login
POST /api/admin/logout
GET  /api/admin/session
PUT  /api/admin/password
```

管理员页面后续请求使用：

```text
x-admin-session-token
```

### 工作区管理

```text
GET    /api/admin/workspaces
POST   /api/admin/workspaces
GET    /api/admin/workspaces/:id
PUT    /api/admin/workspaces/:id
DELETE /api/admin/workspaces/:id

POST   /api/admin/workspaces/:id/bots
DELETE /api/admin/workspaces/:id/bots/:botId
POST   /api/admin/workspaces/:id/bots/:botId/transfer
```

这些接口只接受有效管理员会话或现有管理员 API 凭据。

### 工作区入口

```text
GET  /api/workspaces/:slug/challenge
POST /api/workspaces/:slug/unlock
POST /api/workspaces/:slug/logout
GET  /api/workspaces/:slug/bots
```

工作区会话请求使用：

```text
x-workspace-session-token
```

`GET /api/workspaces/:slug/bots` 只返回现有公开 Bot 列表中的非敏感字段，并限定为当前工作区 Bot。

### 现有接口兼容

- 现有 API 路径保持不变。
- 现有 `x-api-key` 管理员请求继续可用。
- 校验来源从 `.env` 明文比较改为数据库管理员密码 hash。
- 现有 Bot 解锁接口继续接受全局管理员密码并返回 `role=admin`。
- 现有 Bot session、Bot 密码和授权逻辑不变。

## 状态变化规则

### 停用工作区

- 新请求不能解锁。
- 已有工作区 session 立即不能使用。
- Bot 分配和全部业务数据保留。
- 回调和后台任务不受影响。

### 修改工作区口令或 slug

- 增加 `auth_version`。
- 旧 session 立即失效。
- 员工通过新配置重新验证。

### 转移 Bot

- 新工作区刷新后可以看到该 Bot。
- 原工作区刷新后不再显示该 Bot。
- 已经签发的 Bot session 继续维持原有 8 小时有效期，避免打断正在处理的工作。
- 转移不修改 Bot 配置或业务数据。

### 删除工作区

- 删除工作区和对应工作区 session。
- 解除全部 Bot 分配。
- 不删除 Bot、会话、任务、标签、推送、日志或文件。

## 错误处理

- 口令错误：表单内提示并切换失败吉祥物，不刷新整页。
- 管理员密码错误：使用同样的失败状态。
- 工作区不存在：品牌化 404，不泄露其他工作区列表。
- 工作区停用：展示不可用状态，不展示 Bot。
- 工作区 session 过期或失效：返回登录状态并重新对口令。
- 管理员 session 过期：回到管理员登录页。
- Bot 分配冲突：返回该 Bot 已属于其他工作区，由管理员选择转移。
- 管理员凭据初始化失败：管理员写接口不可用，但业务处理链路继续运行。

## 实现边界

采用“独立管理员前端 + 现有控制台轻量工作区上下文”：

- 新增独立 `/admin/` 静态入口和脚本。
- 现有 `/console/` 只增加 slug 解析、工作区认证和 Bot 列表来源。
- 管理员页面和控制台共享基础视觉变量与可复用组件样式。
- 不复制整套会话、任务、标签、推送和日志前端。
- 不把管理员后台作为现有控制台中的大量条件分支。

## 验证

### 数据库

- 一个 Bot 不能同时分配给两个工作区。
- 删除或移除工作区关系不删除 Bot 业务数据。
- 工作区下半句和管理员密码均只保存 hash。
- 修改 slug、上半句或下半句会失效旧工作区 session。

### 认证

- 正确口令签发 30 天固定有效期 session。
- 错误口令不签发 session。
- 停用工作区立即拒绝旧 session。
- 管理员首次从 `.env` 完成一次性初始化。
- 管理员登录、改密、退出和 CLI 重置均正确失效旧会话。
- 现有 Bot 密码和管理员密码解锁语义保持不变。

### 接口

- 工作区接口只返回已分配 Bot。
- `/api/public/bots` 行为保持不变。
- Agent 管理只允许全局管理员。
- 现有 Bot 业务 API 路径和授权测试全部通过。

### 前端

- 未验证工作区不能看到工作区 Bot 列表。
- 对口令成功显示开心吉祥物和完整 3 秒倒计时。
- 对口令失败显示处理后的生气吉祥物。
- 管理员登录复用相同三态交互。
- 工作区页面不出现固定的“部门”“组织”或“工作区”称谓。
- 员工只看到分配给当前 URL 的 Bot。
- Bot 仍需单独解锁，角色和 Tab 权限保持现状。

### 视觉

- 检查三张派生 PNG 的透明通道、边缘和残留背景。
- 失败图不得包含原 DClaw Logo 和“不干了...”文字。
- 在桌面、窄屏和移动端截图验证 Logo、表单、提示、按钮和吉祥物无重叠。
- 状态图片切换时登录容器不能跳动。
- 原始大图不能直接作为页面资源加载。

### 回归

- 全量测试通过。
- WorkTool 回调、AI 回复、会话入库、任务状态机、客户激活、标签、资产、推送和动作执行不受影响。
- 测试环境完成工作区创建、Bot 分配、员工进入、Bot 解锁和管理员配置的完整链路验证后，再上线正式环境。
