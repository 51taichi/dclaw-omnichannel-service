# 会话 Tab 群任务概览设计

## 目标

在“会话”Tab 的群聊详情中，用与私聊“资产”按钮相同的视觉尺寸展示当前群的定时任务概览。用户无需离开会话即可看到任务数量、任务状态和下次执行倒计时；任务的创建与编辑仍统一在“群管理”Tab 完成。

本功能只服务于群聊定时任务，不引入或复用私聊任务状态机，也不改变私聊资产功能。

## 展示边界

- 私聊会话保持现状：右上角显示“资产 已收集数/总数”，点击展开资产面板。
- 群聊会话在同一操作位显示独立的“任务 N”按钮，按钮宽度和视觉风格与私聊资产按钮一致。
- `N` 为当前群全部未删除定时任务数量，包含已启用和已停用任务。
- 群聊不显示资产；私聊不显示群任务概览。
- 会话内只查看任务摘要，不提供启停、编辑、复制、删除、刷新判断或重试操作。

## 任务面板

点击“任务 N”后，在会话头部下方展开轻量任务面板。任务项使用卡片加 icon 的现有视觉语言，并展示：

- 任务名称。
- 任务类型：条件推送或周期汇总。
- 当前状态。
- 下次执行时间及本地实时倒计时。

状态展示规则：

- 已停用任务显示“已停用”，不展示具有误导性的运行倒计时。
- 有客观条件的条件推送任务显示“已达成”或“尚未达成”。
- 周期汇总任务显示“周期汇总”，不虚构达成状态。
- 尚未产生条件判断结果时，继续沿用既有业务规则显示“尚未达成”，不增加“待判断”状态。

面板底部提供“前往群管理”按钮。点击后切换到“群管理”Tab，并自动选择当前会话对应的群，用户可在那里完成所有管理操作。

## 空状态与异常状态

- 群内没有任务时仍显示“任务 0”。点击后显示“暂无群定时任务”，并保留“前往群管理”入口。
- 数据加载过程中按钮显示加载态，避免短暂显示错误的 `0`。
- 加载失败时显示“任务 --”；面板内展示“任务信息加载失败”和“重试”按钮，不把失败误报为没有任务。
- 当前群尚未进入群管理记录时，显示“该群尚未配置”，并引导前往群管理；不请求其他群的数据作为回退。
- 快速切换会话时，旧请求结果不得覆盖新选中的群聊。

## 组件与数据流

会话头部保留一个操作位，但由两个独立组件按会话类型互斥显示：

1. 私聊资产组件继续使用现有资产数据与事件。
2. 群任务概览组件根据当前群聊的 `conversationKey` 解析当前 Bot 下的群记录。
3. 找到群记录后，复用现有 `GET /api/groups/:groupId/automations` 获取序列化任务列表。
4. 面板使用现有任务状态字段和倒计时格式化逻辑，避免在会话页面形成第二套状态规则。
5. 群任务发生实时更新时，仅刷新当前已选群的按钮与面板；离开群聊或切换到私聊时停止相关订阅和倒计时。

若现有会话接口没有稳定返回受管群 ID，则由服务端在 Bot 权限范围内通过 `conversationKey` 解析群记录，并只返回展示所需的安全字段。不得依靠群名匹配，因为群名可重复或修改。

## 隔离与安全

- 所有群记录和任务查询必须同时限定 `botId` 与 `groupId`。
- 不向浏览器暴露群背景、群角色说明、Agent 账本或判断提示词。
- 群任务组件不调用私聊资产、私聊状态机或私聊激活任务接口。
- “前往群管理”必须使用稳定群 ID 定位，不能仅按当前群名查找。

## 布局要求

- “任务 N”与“资产 X/Y”使用相同的固定宽度、最小高度、边框和 icon 尺寸。
- 按钮文字长度、任务数量位数和任务名称长度不能改变会话头部其他区域的位置。
- 任务面板设置合理最大高度；任务较多时面板内部滚动，不撑坏消息区域。
- 任务名称、状态文本和倒计时分别有固定布局职责；长名称省略并通过 `title` 查看全文。
- 窄屏下任务卡从多列摘要降为单列，但操作入口和状态不得重叠或溢出。

## 测试与验收

自动化测试覆盖：

- 私聊只显示资产，群聊只显示群任务，两者互不影响。
- 群任务总数包含已停用任务，但不包含已删除任务。
- 条件推送、周期汇总、已停用和空列表的展示规则正确。
- 加载态、失败重试和未配置群的文案及行为正确。
- 快速切换群聊不会出现跨群数据串写。
- “前往群管理”能够选中正确群，重复群名不会误定位。
- 群任务接口继续执行 Bot 隔离，并且响应不包含群背景等私有上下文。
- 多任务、长名称和窄屏场景不破坏布局。

浏览器验收覆盖桌面宽屏、常规笔记本宽度和窄屏，确认按钮与私聊资产等宽、任务面板内部滚动正常，且任务状态和倒计时在实时更新后保持稳定。
