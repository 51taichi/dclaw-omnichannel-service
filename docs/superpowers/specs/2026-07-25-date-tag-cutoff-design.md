# 添加日期特殊标签组与切日时间设计

## 背景

当前客户添加日期标签只有启用开关，日期值固定按北京时间自然日计算。部分客户公司的业务日不是零点切换，例如每天 20:00 后的新客户应归入次日，因此需要为每个 Agent 配置独立的切日时间。

本次同时统一标签页展示：日期标签不再是普通标签组列表上方的独立开关，而是固定显示在普通标签组之前的特殊标签组。

## 目标

- 标签页第一项固定展示名为“添加日期”的特殊标签组。
- 特殊标签组支持启用和配置切日时间，默认 `00:00`。
- 日期计算统一使用北京时间。
- 修改规则只影响保存之后的新客户，不重算或覆盖任何已有日期标签。
- 保持会话日期筛选、推送日期筛选、标签导入导出和 Agent 级配置隔离可用。

## 非目标

- 不允许修改特殊标签组名称。
- 不允许为特殊标签组新增或删除标签。
- 不支持组内互斥、单向变更、折叠、展开和标签触发任务。
- 不保存完整的历史切日规则版本。
- 不修改普通标签组的数据结构和行为。

## 配置模型

Agent 标签配置中的 `dateTag` 扩展为：

```json
{
  "dateTag": {
    "enabled": true,
    "cutoffTime": "20:00",
    "effectiveAt": "2026-07-25T12:00:00.000Z"
  }
}
```

- `enabled`：是否为新客户创建添加日期标签。
- `cutoffTime`：北京时间切日时间，格式固定为 `HH:mm`，默认 `00:00`。
- `effectiveAt`：当前日期规则的服务端生效时间，使用 UTC ISO 时间保存，由服务端维护，前端不能编辑或指定。

兼容规则：

- 旧配置缺少 `cutoffTime` 时归一化为 `00:00`。
- 旧配置已启用但缺少 `effectiveAt` 时，服务升级启动阶段将部署时刻写为 `effectiveAt`，只作为新规则起点，不回填或重算历史标签。
- 旧配置未启用且缺少 `effectiveAt` 时保持为空，下一次启用时由服务端写入新的生效时间。
- 导出配置包含 `enabled` 和 `cutoffTime`，不导出可复用的 `effectiveAt`。
- 导入配置保存后，由服务端根据是否启用以及规则是否发生变化生成新的 `effectiveAt`。

## 服务端生效规则

服务端保存标签配置时比较旧配置和新配置：

- `false -> true`：设置新的 `effectiveAt`。
- `true -> false`：保留已有日期标签，不再为新客户创建标签。
- 启用状态下 `cutoffTime` 改变：设置新的 `effectiveAt`。
- 启用状态和 `cutoffTime` 都未改变：保留原 `effectiveAt`。
- `true -> false -> true`：重新启用时生成新的 `effectiveAt`，停用期间和重新启用之前的客户不补打标签。

服务启动和保存配置时不再批量重算历史客户日期标签。启动迁移只补齐旧配置的 `cutoffTime` 和 `effectiveAt`，不写入 `conversation_tags`。

创建日期标签前必须同时满足：

1. 日期标签已启用。
2. 客户会话是私聊会话。
3. 客户的本次新增时间不早于当前规则的 `effectiveAt`。
4. 当前会话还没有日期标签。

已有日期标签一旦创建，不因切日时间、启用状态或服务重启而改变。

## 日期计算

计算函数接收客户新增时间和 `cutoffTime`：

1. 将新增时间转换为北京时间的年、月、日、小时和分钟。
2. 将本地时间转换为当天分钟数。
3. 当切日时间不是 `00:00`，且本地时间大于或等于切日分钟数时，业务日期加一天。
4. 输出 `YYYYMMDD`。

示例：

| 切日时间 | 客户新增时间（北京时间） | 日期标签 |
| --- | --- | --- |
| `00:00` | 2026-07-25 00:00 | `20260725` |
| `20:00` | 2026-07-25 19:59 | `20260725` |
| `20:00` | 2026-07-25 20:00 | `20260726` |
| `20:00` | 2026-12-31 20:00 | `20270101` |

`00:00` 是兼容特例：为保持现有自然日行为，`00:00` 不执行加一天，仍按当前北京时间日期打标。其他切日时间在达到该时间后归入次日。

## 新客户识别与写入

日期标签沿用当前新客户识别入口：

- canonical 新增好友系统问候触发的新客户流程；
- 新建私聊会话时的安全补偿入口。

两个入口调用同一个日期标签写入函数，写入函数负责检查 `effectiveAt`、现有日期标签和会话类型，保证幂等。

好友删除后重新添加会先重置旧会话并创建新的会话周期，因此本次新增时间使用当前规则计算，不沿用上一次添加日期。

## 标签页 UI

特殊标签组固定渲染在普通标签组列表的第一项，样式与普通标签组头部保持一致：

- 启用开关。
- 固定标签组名称“添加日期”，使用只读文本展示，不使用文本输入框。
- “切日时间”图标、标签和原生时间选择器。
- 默认值 `00:00`。

不渲染以下控件：

- 组内互斥。
- 单向变更。
- 新增标签。
- 删除标签组。
- 折叠或展开。

普通标签组仍从第二项开始，现有新增、删除、折叠、互斥和单向变更逻辑不变。

## 筛选与展示

- 客户卡片继续显示计算后的 `YYYYMMDD` 日期标签。
- 会话页“添加日期”筛选继续按 `YYYYMMDD` 查询。
- 推送页“按添加日期选择”继续按 `YYYYMMDD` 选择目标。
- 日期标签不进入普通多标签选择组件。
- 日期标签不交给 Agent 判定，也不支持标签触发任务。

## 错误处理

- 非法或缺失的 `cutoffTime` 归一化为 `00:00`。
- 前端时间选择器清空时恢复为 `00:00`。
- 客户新增时间无效时不创建日期标签，并记录结构化告警日志。
- 保存配置失败时保持当前服务端配置不变，前端显示失败提示。
- 重复回调通过现有会话和标签唯一约束保持幂等，不创建第二个日期标签。

## 测试

### 单元测试

- `cutoffTime` 归一化和旧配置兼容。
- `00:00` 保持现有自然日语义。
- `20:00` 前后边界。
- 月末、年末和闰日跨日。
- 北京时间与 UTC 转换。

### 数据库测试

- 首次启用生成 `effectiveAt`。
- 旧版已启用配置在升级时生成 `effectiveAt`，且不回填历史会话。
- 修改切日时间更新 `effectiveAt`。
- 未修改日期规则时保留 `effectiveAt`。
- 停用和重新启用生成新的生效时间。
- 已有日期标签不重算、不覆盖。
- 生效时间之前的历史会话不补打标签。
- 生效时间之后的新客户按当前规则打标。

### 服务端测试

- 新增好友流程使用 Agent 当前切日时间。
- 重复新增好友回调不重复创建标签。
- 删除后重新添加按新会话时间和当前规则打标。
- 普通私聊、群聊、AI 回复激活和标签触发任务不受影响。

### 控制台测试

- 特殊标签组固定在第一位。
- 特殊标签组不可新增、删除或折叠。
- 不显示互斥和单向变更控件。
- 时间选择器默认 `00:00` 并正确保存。
- 导入旧配置时显示 `00:00`。
- 普通标签组现有功能保持不变。
