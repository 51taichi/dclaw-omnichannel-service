# 推送标签选择与定时推送设计

## 目标

在不改变其他 tab 功能的前提下，为推送 tab 增加按客户标签自动选择目标和一次性定时推送能力。现有的手动选择、全选私聊、全选群组、清空和立即发送继续可用。

## 边界

- 功能只作用于推送 tab、主动推送 API、主动推送数据库任务和主动推送 worker。
- 普通会话消息、AI 回复、任务激活、标签激活、群聊处理和其他 tab 不改变行为。
- 定时推送为一次性任务；执行前可以取消，已经发送到 WorkTool 的消息不撤回。
- 标签只用于匹配私聊客户。群组仍使用现有全选群组或手动选择能力。
- 选择多个标签时采用 OR 规则：客户拥有任意一个已选标签即匹配。
- 标签选择加入现有选择集合，不清除手动选择、全选私聊或全选群组形成的选择；同一目标按 `targetType:targetName` 去重。

## 用户界面

推送 tab 的目标工具栏保留现有目标类型切换、搜索、全选私聊、全选群组、清空和分页。新增一个紧凑的标签选择控件：标签按标签组展示，日期标签单独展示；选择标签后，前端调用服务端获取该 Bot 下所有匹配客户并加入已选目标集合。没有匹配客户时显示提示，不影响已有选择。

消息内容区域新增“定时推送”开关。开关关闭时，提交按钮继续显示“创建并发送”，创建后沿用当前立即发送流程。开关打开后显示北京时间的 `datetime-local` 输入框，提交时仍使用“创建并发送”，但任务只进入待定时状态，不立即发送。时间必须晚于当前时间。

主动推送查询列表增加定时任务的时间信息和取消操作。待定时、待发送或发送中的任务允许点击取消；取消后任务显示“已取消”，未领取的目标不再发送。

## 服务端与数据库

### 标签匹配

扩展主动推送目标查询能力，提供按 Bot 查询当前存在标签的私聊目标。查询通过绑定的 `agent_id` 和 `conversation_tags` 关联 `proactive_targets`，同时支持普通标签和日期标签，返回全量匹配目标而不受 UI 分页限制。接口按请求 Bot 做访问校验，不接受客户端传入 agent 作为信任边界。

### 定时任务

在 `proactive_tasks` 增加可空的 `scheduled_at` 字段：

- `NULL` 表示立即发送，兼容所有已有任务。
- 非空表示一次性执行时间，使用服务端统一的 ISO 时间值保存。
- API 将浏览器传入的本地日期时间转换为明确的北京时间语义后再保存，拒绝非法或不晚于当前时间的值。

主动推送 worker 领取目标时增加任务时间条件：只有任务为立即任务，或 `scheduled_at <= now`，且目标状态为 `pending` 的目标才可领取。领取顺序仍按目标子任务 ID 升序，因此同一个任务会依次发送。

取消 API 按 Bot 校验任务归属，只允许未完成任务。数据库事务将该任务下所有 `pending` 目标标记为 `canceled`，将任务状态标记为 `canceled` 并记录取消时间和原因；已发送目标保持原状态。worker 领取前的状态条件和事务更新保证取消后的未领取目标不会继续发送。

### 状态与兼容性

立即任务继续创建 `pending` 任务并唤醒 worker。定时任务创建后不唤醒发送动作，后台定时轮询自然在时间到达后领取。任务状态保留现有 `pending`、`sending`、`sent`、`partial`、`failed`，新增 `canceled`；定时未到时间通过 `scheduled_at` 与 `pending` 区分，不新增另一套目标表或 worker。

## API

- `GET /api/proactive/targets/tags?botId=...`：返回该 Bot 下可用于推送选择的标签，包含标签类型、组信息、标签 ID 和名称。
- `GET /api/proactive/targets?botId=...&tagType=...&groupId=...&tagId=...`：增加单标签匹配参数，服务端返回分页目标；前端按分页接口读取全部匹配目标。
- `POST /api/proactive/tasks`：接收可选 `scheduledAt`，立即任务不传或传空，定时任务传标准化时间。
- `POST /api/proactive/tasks/:taskId/cancel`：取消指定 Bot 的未完成主动推送任务。

任务详情和任务列表响应增加 `scheduledAt` 及取消相关时间/状态字段，保持已有字段不变。

## 错误处理

- 没有 Bot、目标、消息内容或附件时继续使用现有校验。
- 标签接口失败不清空现有选择，前端显示错误提示。
- 定时时间格式错误或早于等于当前时间时，服务端拒绝创建并返回明确错误。
- 取消不存在任务、跨 Bot 任务或已结束任务时返回明确错误，不改变任务状态。
- worker 只有在数据库成功领取 `pending` 目标后才发送，发送失败继续沿用现有重试和任务状态统计。

## 测试策略

- 数据库测试标签查询能跨分页返回全部匹配私聊目标，多个标签按 OR 合并且目标去重。
- 数据库测试立即任务可被领取，未到时间的定时任务不能被领取，到时可按 ID 顺序领取。
- 数据库测试取消任务后 pending 目标变为 canceled，worker 无法再领取，已发送目标保持 sent。
- 服务端边界测试验证 API 传递 `scheduledAt`、标签查询参数、Bot 访问校验和取消路由。
- 控制台边界测试验证标签选择控件、定时开关/日期时间输入、任务取消按钮，以及现有全选私聊/全选群组和立即发送仍存在。
- 运行完整 `npm test`，确保其他 tab 和现有主动推送行为没有回归。
