# 人工回复多附件设计

## 目标

会话 Tab 中处于“人工接手”的会话，可以在当前回复框中选择并发送最多 5 个附件。附件上传、类型识别和 Whapi 媒体发送规则与推送 Tab 保持一致，但接收目标固定为当前会话。

文本可以留空：

- 只有文本时发送普通文本消息；
- 只有附件时按选择顺序发送附件；
- 文本和附件同时存在时，文本作为第一个附件的说明发送。

## 页面布局

人工回复框保持现有结构并增加两个区域：

- 上传附件按钮：使用 Icon 按钮，位于文本输入框右上角；点击后打开支持多选的文件选择器。
- 附件预览区：位于底部工具栏中，处在预置表情与发送按钮之间，横向排列。

附件预览默认只显示与类型对应的 Icon（图片、视频、音频、文件），不常驻显示文件名。鼠标悬停或键盘聚焦时显示完整文件名。每个附件提供可访问的删除操作，允许发送前移除单个附件。

最多选择 5 个附件。达到上限后继续选择时给出提示，只保留允许数量。AI 接管状态下，上传、删除和发送均不可操作，并清空未发送的本地附件选择，避免切换会话后误发。

## 前端数据流

前端为人工回复维护独立的附件文件列表，不与推送 Tab 的附件列表共享状态，但复用以下通用能力：

- 文件类型识别；
- 单文件上传接口 `/api/uploads`；
- 最多 5 个附件规则；
- 上传进度与错误提示。

点击发送时：

1. 固定当前 Bot、会话键和上下文版本。
2. 校验文本或附件至少存在一项，并再次确认会话仍为人工接手。
3. 按列表顺序逐个上传附件。
4. 将上传结果转换为 `{ fileUrl, objectName, fileType }` 数组。
5. 调用当前会话的人工回复接口，提交 `content` 与 `attachments`。
6. 服务端全部接受后清空文本和附件并刷新会话。

上传或发送失败时保留文本和本地附件选择，允许用户修正或重试。切换 Bot、切换会话、恢复 AI 接手或删除会话时清空附件选择。

## 服务端接口与发送

扩展：

```text
POST /api/flow-sessions/:conversationKey/manual-reply
```

请求体：

```json
{
  "botId": "whatsapp-sales-01",
  "content": "可选说明文字",
  "attachments": [
    {
      "fileUrl": "https://support.example/uploads/...",
      "objectName": "price-list.pdf",
      "fileType": "file"
    }
  ]
}
```

服务端复用推送消息的附件规范化规则：最多 5 个，类型仅允许 `image`、`video`、`audio`、`file`。接口继续校验 Bot 权限、会话归属、人工接手状态、启用的 Bot 绑定与当前发送目标。

发送规则：

- 没有附件：沿用文本发送逻辑；
- 有附件：按数组顺序逐个调用标准 Channel 媒体发送；
- 说明文字只附加到第一个附件，其余附件说明为空；
- 每个成功发送的 Provider Message ID 都保存到出站记录，以便状态回调关联。

## 会话记录与失败语义

一次人工提交在会话中写入一条 outbound 会话记录，`rawPayload.attachments` 保存成功发送的附件描述和对应 Provider Message ID，文本内容保留用户输入；纯附件消息使用可读的附件摘要作为会话内容。

每个成功发送的附件分别写入 `outgoing_messages`，从而独立更新 sent、delivered、read 或 failed 状态。

发送采用顺序执行。若某个附件失败：

- 停止发送后续附件；
- 已成功发送的附件和出站记录必须保留；
- 接口返回部分失败信息，不把已发送附件伪装成未发送；
- 前端保留原输入并显示失败位置，用户刷新后可以从会话记录确认已发送内容。

## 测试

测试覆盖：

1. 人工回复允许纯文本、纯附件、文本加附件。
2. 非人工接手状态拒绝文本和附件发送。
3. 附件最多 5 个并拒绝未知类型。
4. 多附件按顺序发送，说明文字只用于第一个附件。
5. 每个成功附件写入独立出站记录并可接收状态回调。
6. 部分失败保留已成功发送记录并停止后续发送。
7. 前端上传按钮位置、附件 Icon 预览、Hover 文件名和单项删除行为。
8. 切换 Bot、会话或恢复 AI 时清空未发送附件。
9. 上传/发送失败时不清空文本与附件选择。
