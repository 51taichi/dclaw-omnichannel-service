# 顺序激活话术设计

## 目标

将私聊状态机节点中的客户激活，从节点级统一间隔和次数，改为按话术逐条推进。每条话术独立定义等待时间与发送次数；同一客户在同一节点中，已完成话术不会再次发送。

## 配置模型

节点保留一个统一的 `polishByAgent` 开关。激活配置改为：

```json
{
  "enabled": true,
  "polishByAgent": true,
  "messages": [
    {
      "content": "道友，刚给你发学习资料，看过了吗？",
      "intervalMinutes": 2,
      "maxTimes": 1
    },
    {
      "content": "再提醒您一下，晚上有直播课。",
      "intervalMinutes": 30,
      "maxTimes": 2
    },
    {
      "content": "需要的话我可以继续给您说明。",
      "intervalMinutes": 120,
      "maxTimes": 1
    }
  ]
}
```

旧版节点级 `intervalMinutes` 和 `maxTimes` 在读取时迁移为每条话术的默认值，避免已有状态机无法使用。

## 会话进度

每个私聊会话、每个当前节点保存独立的激活进度：

- 当前未完成话术索引。
- 当前话术已成功发送次数。
- 当前计时对应的节点与话术版本。

进度随会话和节点存在，不与 Bot 的其他客户共享。已达到 `maxTimes` 的话术永久完成；后续 AI 回复不会使其回退。

## 计时和发送

1. 新增好友回调仅对入口节点启动话术 1 的首次倒计时。
2. AI 在私聊中成功回复后，为当前节点当前未完成话术启动或重启倒计时。
3. 某次话术成功发送后，从该次发送时间开始安排下一次：
   - 同一话术的第 N 次发送，等待 `intervalMinutes × 2^(N-1)`。
   - 当前话术完成后，下一条话术的第一次发送等待其自身 `intervalMinutes`。
4. 当前有效机器人回复是计时锚点。新增好友回调是入口节点首次计时的例外锚点。

示例：话术 1 为 2 分钟 1 次，话术 2 为 30 分钟 2 次，话术 3 为 120 分钟 1 次。话术 1 发送后，30 分钟后发送话术 2 第一次；话术 2 第一次发送后，再等待 60 分钟发送第二次；话术 2 完成后，再等待 120 分钟发送话术 3。

## 取消与状态切换

- 客户任意私聊互动，包括不支持交给 Agent 的图片、表情等非文本消息，立即取消当前待发送任务。
- 客户回复不会倒退已完成话术。AI 再回复后，只为当前未完成话术的当前次数重新计时。
- 节点发生变化时，旧节点的待发送任务和激活进度立即失效；新节点从话术 1、发送次数 0 开始。
- 人工接手、清空会话、重新绑定 Agent 同样取消未完成任务；清空会话会清空该会话的激活进度。

## 控制台

- 移除节点级“激活间隔（分钟）”和“激活次数”。
- 每条激活话术以独立卡片显示：内容、间隔分钟、发送次数、删除按钮。
- 节点保留启用激活、Agent 美化话术和新增话术操作。
- 旧状态机打开后可直接编辑；保存时写入新版话术配置。

## 可靠性与验证

- 任务写入时包含节点、话术索引、该话术发送次数和会话进度代际。
- Worker 发送前和发送后均核对任务是否仍为当前有效任务，防止客户回复、节点切换或人工接手后误发。
- 覆盖新增好友、AI 回复重计时、客户回复取消、同一话术多次、跨话术推进、节点切换和旧配置迁移的自动化测试。
