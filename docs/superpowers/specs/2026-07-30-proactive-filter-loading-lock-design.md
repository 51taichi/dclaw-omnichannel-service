# 主动推送交叉筛选 Loading 锁设计

## 目标

避免用户快速切换主动推送筛选条件时产生并发请求，导致较早发出的请求较晚返回并覆盖最新筛选状态。

## 交互

- 日期、标签、搜索、目标类型、同步名单、全选、清空和分页共用一个筛选锁。
- 任一筛选请求开始后，目标选择区域立即进入 loading 状态。
- loading 期间禁用全部筛选控件、目标卡片和分页，关闭已打开的标签菜单。
- 目标区域显示轻量半透明遮罩、加载图标和“正在筛选”提示，不改变现有布局尺寸。
- 请求无论成功、失败或因 Bot 上下文切换而失效，都必须释放筛选锁。

## 实现边界

- 在前端状态中增加主动推送筛选 loading 标记。
- 通过统一的异步包装函数管理加锁和解锁，所有会触发目标数据请求的交互复用该入口。
- 保留现有接口和筛选规则，不修改服务端 API。
- Bot 切换和内容重置时强制清理 loading 状态，避免新 Bot 被旧请求锁住。

## 测试

- 验证筛选请求执行期间所有相关控件均不可操作。
- 验证重复筛选不会启动第二个并发请求。
- 验证成功和失败后都会恢复操作。
- 验证 Bot 切换后旧请求不能影响新 Bot 的 loading 状态。
- 运行控制台相关测试及全量测试。
