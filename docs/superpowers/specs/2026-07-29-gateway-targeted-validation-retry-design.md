# Gateway 定点校验重试设计

## 背景

生产环境中，Agent 返回了一个业务字段完整的 JSON 对象，但在对象后附加了内部执行说明。首次校验失败后，Gateway 让 Agent 重新生成整个回复；重试结果保留了原业务回复，却仍遗漏一个必须评估的标签，最终触发失败兜底话术。

## 目标

1. 当响应中只有一个完整、合法的 JSON 对象时，Gateway 可以移除对象外的说明文字并继续严格校验。
2. 当严格校验失败时，重试请求携带上一版 JSON、校验错误和完整标签清单，让 Agent 定点修正，而不是脱离上一版结果重新生成。
3. 所有启用标签仍必须逐一评估。Gateway 不推断缺失标签为 `false`，不放宽标签审计。

## 边界

- 不修改 Agent、任务节点、标签配置和标签状态机。
- 不增加“自动打标”开关。
- 多个不同 JSON 对象、截断 JSON、闭合但非法的候选对象继续拒绝。
- JSON 提取后仍需通过现有结构、状态机、标签证据及标签决策校验。
- 重试携带的上一版响应必须有长度上限，避免请求无限增长。

## 实现

`validateAgentResponseText` 在直接 `JSON.parse` 失败后扫描完整 JSON 对象。只有扫描结果恰好对应一个合法对象，或多个内容完全相同的合法对象时，才执行确定性修复。存在截断候选、非法候选或多个不同对象时返回原语法错误。

`buildAgentResponseValidationRetryRequest` 接收上一版原始响应和标签上下文。重试提示包含：

- 校验错误；
- 有界的上一版响应；
- 每个必须评估的 `groupId:tagId` 及达标条件；
- 明确要求 `tagEvaluation` 对每个标签恰好返回一次。

重试结果仍走同一套严格校验，失败时保持现有兜底行为。

## 测试

- 用生产 `Wen` 响应形态验证“唯一 JSON + 尾随说明”可本地提取。
- 验证多 JSON、截断 JSON和非法候选仍被拒绝。
- 验证重试请求包含上一版响应、缺失标签及全部标签清单。
- 验证重试补齐遗漏标签后成功，且没有把缺失标签本地伪造为 `false`。
