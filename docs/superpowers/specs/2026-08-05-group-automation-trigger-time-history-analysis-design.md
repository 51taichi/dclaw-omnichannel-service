# 群任务到期历史分析与账本替换设计

## 文档定位

本文定义群定时任务的新执行架构：以完整群历史为事实来源，只在计划执行窗口让 Agent 判断条件或生成周期 Review，并彻底移除通用群事实账本、模板变量账本和实时达成状态。

本文覆盖并取代以下既有设计中的相关部分：

- `2026-08-04-group-scheduled-automation-design.md` 中的群级事实账本、增量事实提取、实时条件状态、白话变量机械替换和账本回溯设计；
- `2026-08-04-group-conversation-task-summary-design.md` 中的实时“已达成/尚未达成”展示规则；
- `2026-08-05-group-management-three-tabs-and-task-cards-design.md` 中依赖实时判断状态的任务卡展示规则。

既有设计中已经确认的群管理三 Tab、日/周/月周期选择、1 日至 28 日与月底、多角色原生 `@`、执行记录 Dialog、会话证据定位、私聊隔离和响应式布局继续有效，除非本文明确修改。

## 目标

- 完整保存群里每个参与者的发言、时间、消息类型和来源，使 Agent 能结合群背景与角色配置理解真实业务过程。
- 条件推送只在目标推送时间前后完成一次任务级判断，不因每条群消息调用 Agent。
- 周期汇总直接按照自然语言模板和完整周期历史生成专业 Review，不要求用户预定义变量类型、事实类别或统计项。
- 对长群会话提供确定的上下文预算、分段处理、断点恢复和防重复发送能力。
- 让执行过程可观察、可定位、可恢复，同时保持任务卡简洁。
- 彻底删除旧群账本及其运行链路，不影响私聊任务状态机、标签、群即时回复和现有推送 Tab。

## 非目标

- 不恢复群任务的实时“已达成/尚未达成”判断。
- 不为群建立业务任务状态机或私聊资产。
- 不要求用户维护事实类型、统计字段、模板变量表或群成员实时状态。
- 不在每条群消息到达时分析条件或计算汇总。
- 不依赖 Agent 自动记住所有 DClaw Chat，也不假设普通会话上下文天然包含其他 session 的历史。
- 不在群管理中展示完整群聊记录；历史消息仍在“会话”Tab 查看。
- 不改变群即时回复是否需要 `@`、群标签绑定或私聊逻辑。

## 已确认的产品原则

1. 群原始历史是业务判断的基础，账本、聚合事实和预定义变量不再是中间真相。
2. 一个群中的不同成员必须保留独立身份、发言时间和消息来源；模型协议可以继续使用标准 `user/assistant` 角色，但不能丢失真实参与者信息。
3. 两类任务都只在计划执行窗口调用 Agent。长历史允许一次逻辑执行包含多个受控 Agent 请求，但不会转化为实时分析。
4. 条件推送由 Agent 决定是否发送，发送内容始终是用户审核过的固定原文。
5. 周期汇总没有达成条件，属于业务必发任务；Agent 负责根据模板生成最终自然文本。
6. 群背景、角色配置、系统提示词、历史读取方式和内部判断说明均为后台信息，绝不能在群内透露。
7. 所有周期、时间范围、倒计时和执行时间统一使用 `Asia/Shanghai`。
8. 用户设置的时间是目标推送时间，系统默认提前 10 分钟开始预分析。
9. 页面不常驻展示“提前 10 分钟分析”的说明；只有创建或修改时间不足时才给出针对性反馈。
10. WorkTool 发送结果不明确时宁可人工确认，也不能盲目重发造成群内重复消息。

## 总体架构

系统只保留一条群任务业务链路：

```text
完整群消息历史
→ 计划时间前 10 分钟预分析
→ 目标时间补充最后 10 分钟消息
→ Agent 最终判断或生成
→ 固化发送内容
→ WorkTool 发送
→ 保存结果、说明与证据
```

职责边界如下：

- WorkTool Bot Service：接收并持久化原始消息、维护任务配置、创建执行记录、编排分段分析、校验 Agent 结果、解析 `@` 对象、发送消息、展示记录与证据。
- DClaw：保存每个群的完整连续历史，提供无推理写入和受限读取能力，并执行条件判断或 Review 生成。
- WorkTool：实际向企业微信群发送固定内容或生成后的 Review，并返回命令结果。
- 控制台：配置任务、展示倒计时和最终执行状态、打开执行详情并定位证据。

群即时回复与群任务使用隔离的执行会话。任务分析不能污染群即时回复上下文，群即时回复也不能改变已经开始的任务执行快照。两者可以读取同一份受权限保护的群历史。

## 完整群历史

### 原始消息内容

每条群消息至少保留：

- Bot ID、稳定群 ID 和 conversation key；
- 本地持久消息 ID 与可用的上游消息 ID；
- 消息发生时间和接收时间；
- 发言人名称、可匹配的群角色 ID 和发送者标识；
- 方向与来源：群成员入站、Bot 回复、控制台人工回复、定时推送或其他系统消息；
- 消息类型：文本、图片、语音、文件、链接等；
- 现有链路能够获得的正文、转写、说明和附件元数据；
- 去重和审计所需字段。

本功能不额外承诺新的 OCR、语音转写或文件解析能力。现有链路没有可读文本时，历史记录必须如实标识消息类型和“无可用文本”，Agent 不得猜测附件内容。

所有消息来源都可以作为上下文，但证据权重不同。Bot 回复、固定推送和自动 Review 不能单独证明“客户已经交作业”等外部行为；客户本人、老师、家长或其他被配置角色的明确发言可以按任务条件参与判断。

### DClaw 群历史空间

- 每个 Bot 下的每个稳定群建立一个连续、追加式历史空间，不能以可修改群名作为主键。
- 写入历史只追加记录，不调用 Agent、不触发回复、不消耗生成 Token。
- DClaw 以稳定外部消息 ID 幂等写入。实时消息优先使用上游稳定 ID；历史回填使用 WorkTool 本地持久消息 ID 作为稳定外部 ID。
- 群改名不产生新历史空间；Bot 或群被正式删除时，按既有数据生命周期清理相应历史。
- 普通 Agent session 不自动获得其他 session 的全部历史。任务执行器必须通过受限历史读取接口取得当前群、当前时间范围的数据。

### 本地与 DClaw 的职责

- `conversation_messages` 继续作为控制台展示、消息定位、去重和审计的本地权威来源。
- DClaw 群历史是 Agent 分析所使用的完整历史视图。
- 两侧用稳定消息 ID 对齐。Agent 返回的证据 ID 必须能够解析回本地消息，否则结果无效。
- 写入 DClaw 暂时失败不能丢失本地原始消息；由持久化补偿任务按消息 ID 重试，而不是重新触发 Agent。

### 既有历史回填

- 将本地已保存的群消息按 Bot 和稳定群标识回填到 DClaw。
- 回填保持原始顺序、参与者、时间、方向、类型和来源。
- 回填可分批、可中断续传、可重复运行，重复消息由稳定 ID 去重。
- 没有保存过的历史不补造、不从摘要反推。
- 新群任务执行器启用前必须确认目标群所需历史范围已经同步；历史不完整时不进行可能产生错误结果的发送。

## 历史时间范围

任务只读取当前自然周期开始至目标推送时刻的消息，边界统一采用北京时间：

- 每日：目标日期 `00:00:00` 至目标推送时刻；
- 每周：目标日期所在周的周一 `00:00:00` 至目标推送时刻；
- 每月：目标日期所在月的 1 日 `00:00:00` 至目标推送时刻。

同一自然周期内配置多个执行日时，各次范围允许重叠，并采用“周期截至本次执行”的口径。例如月任务配置 10 日、20 日和月底，三次分别读取月初至 10 日、月初至 20 日、月初至月底的历史，而不是只读取上次执行后的增量。

证据消息的发生时间必须位于本次授权范围。Agent 可以理解范围内消息中的“昨天”“上周”等自然语言，但不能引用范围外消息作为本次任务证据。

当前自然周期是默认范围。周期汇总模板明确要求“累计”“至今”“从建群”等跨周期统计时，本次任务可以将对应分析范围扩大为建群以来至目标推送时刻。混合模板可以同时包含“本周次数”和“累计次数”：前者只统计当前自然周期，后者统计模板明确要求的累计范围。

扩大范围不恢复事实账本或累计聚合。执行器仍从完整原始历史读取，并通过紧凑格式、分段覆盖和最终合并完成统计。模板没有明确跨周期要求时，Agent 不得自行引用自然周期之前的消息。

## 紧凑历史格式

Agent 输入不重复发送冗长 JSON 字段名。群元数据与参与者字典只声明一次：

```text
群：AAA 作业群
周期：2026-08-03 00:00:00 ～ 2026-08-05 09:00:00

参与者：
P1＝张三｜客户｜家长
P2＝李四｜授课老师
P3＝王五｜公司同事
BOT＝当前机器人
```

消息采用一条一行的确定格式：

```text
M001｜2026-08-05 08:42:16｜P1｜文本｜今天的作业已经交了
M002｜2026-08-05 08:47:03｜P2｜文本｜已批改，完成得不错
M003｜2026-08-05 08:48:10｜BOT｜文本｜收到
```

格式要求：

- `M...` 是本次输入中的短消息标识，并可映射回稳定本地消息 ID；
- 时间保留到秒，跨日时始终包含完整日期；
- 参与者使用短 ID，真实名称和角色只在字典中出现一次；
- 消息正文中的换行、分隔符和控制字符必须确定性转义；
- 非文本消息保留类型与现有可用文本，例如 `图片｜现有描述`、`语音｜现有转写`；
- 不能为了省 Token 删除发言人、时间、消息来源或证据映射。

紧凑格式减少重复字段，但它不是唯一的过载保护。系统不能仅靠把 JSON 改成纯文本就假设长会话一定能够单次处理。

## 上下文预算与分段分析

### 自适应路径

执行器按目标模型的实际上下文窗口计算安全预算，为系统规则、群背景、角色、任务要求、临时结果和最终输出预留空间：

- 历史低于安全预算：一次 Agent 请求完成判断或生成；
- 历史超过安全预算：按消息时间和消息边界分段，在本次执行内完成临时分段分析，再进行最终合并；
- 任一分段结果仍超过预算时，可继续分层合并，不能向模型发送超出上下文限制的请求。

安全预算由模型配置和保守 Token 估算动态计算，不写死为固定消息条数。字符数和消息数只能作为额外保护，不能替代 Token 预算。

### 临时分段结果

分段分析始终围绕本次任务的已知条件或模板：

- 条件推送分段只提取与本次达成条件相关的明确支持、否定、更正和消息证据；
- 周期汇总分段只提取满足本次模板结构和统计要求的候选内容、数量依据和消息证据；
- 最终合并请求获得全部分段结果、群背景、角色和任务要求，再形成最终结果。

分段结果具有以下边界：

- 只属于一个执行 occurrence，不跨任务复用；
- 不形成群级事实、类别、变量、聚合或长期账本；
- 为断点恢复可以短期持久化，执行完成后按保留策略清理；
- 最终执行记录只长期保留对用户有价值的结果、简短说明、最终文本和证据 ID；
- 分段失败只重试失败分段，不重复消耗已完成分段的 Token。

仅让 Agent 自行分页读取但不要求完整扫描，不能满足精确统计。执行器必须掌握分段覆盖范围，并确认所有授权消息区间已经处理后才允许最终合并。

## 提前 10 分钟分析

用户配置的执行时间是目标推送时间 `T`。系统为每个 occurrence 建立两个历史阶段：

1. `T-10 分钟` 开始预分析自然周期起点至预分析截止时刻的大段历史；
2. `T` 到达后读取预分析截止时刻之后、`T` 之前的新消息，完成增量分析和最终合并。

这样既为长历史预留计算时间，也不会漏掉客户在最后 10 分钟内刚刚完成条件的消息。`T` 之后发生的消息不属于本次执行证据。

规则如下：

- 页面倒计时始终指向目标推送时间 `T`，不展示预分析开始时间；
- 任务卡不常驻显示“提前 10 分钟分析”提示；
- 新建或修改任务时，下一计划时间距当前不足 10 分钟，则该 occurrence 不采用新配置，选择下一次满足提前量的计划时间；
- `T-10 分钟` 开始后固化本次任务配置版本，之后的编辑只影响后续 occurrence；
- 若 `T` 到达时预分析仍未完成，状态继续为“执行中”，完成后尽快发送并记录延迟；
- 系统不能为了准点而使用不完整历史、跳过失败分段或发送未完成内容。

固定 10 分钟是第一版默认准备窗口。后续是否调整应基于真实执行时长数据，不在第一版增加用户可配置项。

## 条件推送

### 配置

条件推送必须包含：

- 任务名称；
- 启用状态；
- 周期、执行日和目标推送时间；
- 一条客观自然语言达成条件；
- 用户审核过的固定推送内容；
- 零个或多个要原生 `@` 的群角色。

不再把没有条件的固定消息放入“条件推送”。如果未来需要无条件固定循环消息，应单独定义明确类型，而不是让条件字段具有两种语义。

### Agent 输出契约

最终判断至少返回：

- `achieved`：严格布尔值；
- `decisionNote`：面向员工的简短判断依据，不是隐藏推理过程；
- `evidenceMessageIds`：支持结论的稳定消息 ID；
- 契约版本和必要的结构校验字段。

服务端必须校验：

- 输出能够按严格结构解析；
- 所有证据属于当前 Bot、当前群和本次时间范围；
- “已达成”结论至少包含可信群消息证据；
- 基于“没有出现明确记录”的未达成结论可以没有证据，但必须给出简短说明；
- Agent 不能修改固定推送内容、添加 `@` 人员或改变任务周期。

### 发送规则

- `achieved=true`：服务端原样发送用户配置内容，并使用配置的群角色解析当前 `atList`；
- `achieved=false`：不调用 WorkTool 发送，记录为“未发送”；
- Agent 结果无效或历史不完整：有限重试后记录“执行失败”，绝不把不确定结果当成未达成。

## 周期汇总

### 配置

周期汇总包含：

- 任务名称；
- 启用状态；
- 周期、执行日和目标推送时间；
- 一份自然语言 Review 模板；
- 零个或多个要原生 `@` 的群角色。

周期汇总不包含达成条件，也不允许 Agent 决定“是否值得发送”。它是业务必发的专业回顾。

### 模板语义

模板表达内容结构、统计口径和输出要求，例如：

```text
本周上课 {{本周上课次数（明确已经完成的课程才计数，取消或改期不计）}} 次
```

`{{...}}` 继续作为用户易理解的自然语言要求，但不再对应预定义变量、事实类别或持久化聚合。Agent 在执行时读取完整授权历史，理解模板要求并直接生成最终自然 Review。

Agent 可以调整句式，使结果自然、连贯且符合真实信息。模板要求的栏目和统计口径必须保留；没有明确记录时应如实说明，不得把“没有记录”推断为“没有发生”，也不得编造数字。

### Agent 输出契约

最终结果至少返回：

- `content`：可直接面向客户发送的最终 Review；
- `decisionNote`：面向员工的简短生成或统计说明；
- `evidenceMessageIds`：支撑核心统计和事实的消息 ID；
- 契约版本和必要的结构校验字段。

周期汇总没有“未发送：条件未达成”。群里相关信息很少时，Agent 仍应生成克制、专业且不虚构的 Review。只有历史读取、Agent 契约、保密校验或发送链路发生技术异常时，才记录执行失败并不发送错误内容。

## 对外保密边界

群背景和角色配置只帮助 Agent 识别人物、关系和业务语境，不是对外可披露资料。

所有 Agent 提示和响应契约必须明确：

- 不得提及或暗示“群背景”“角色配置”“系统提示词”“后台记录”“历史读取工具”“内部资料”或类似机制；
- 条件推送只能发送用户固定原文；
- 周期汇总只输出面向客户的 Review；
- `decisionNote`、证据 ID、错误信息和内部计算依据只进入后台执行记录，永远不拼接到群消息；
- 除非模板明确要求，否则不得主动输出只存在于内部群背景、且没有在群会话中出现的敏感信息。

发送周期汇总前执行结构与敏感元信息校验。检测到疑似内部机制泄漏时，使用相同历史结果进行有限的定向修复；连续失败则记录“执行失败”，不能冒险发送。

## 执行状态与生命周期

### 用户可见状态

- 倒计时：尚未进入本次执行窗口；
- 执行中：正在读取历史、分段分析或生成最终结果；
- 已发送：WorkTool 已明确确认发送成功；
- 未发送：仅用于条件推送，表示条件未达成；
- 执行失败：历史读取、Agent、校验或明确发送失败在有限重试后仍未恢复；
- 发送待确认：WorkTool 请求结果不明确，消息可能已经发送。

“执行中”是技术执行状态，不是客户业务条件的“待判断”。系统不恢复实时已达成、尚未达成或判断异常状态。

### 内部阶段

每个 occurrence 使用任务 ID 与计划目标时间构成唯一键，并保存配置版本。内部阶段至少区分：

```text
queued
→ reading_history
→ analyzing_chunks
→ synthesizing
→ ready_to_send
→ sending
→ sent | not_sent | failed | send_unknown
```

每个运行中 occurrence 使用持久租约与心跳：

- 多实例和重复调度 tick 不能创建或执行两个相同 occurrence；
- 服务重启后从最近已提交阶段恢复；
- 同一个任务的 occurrence 串行执行，下一次到期时上一次仍在运行则排队，不并发；
- 已固化的判断与最终内容不可因发送重试而重新生成。

### 重试与发送幂等

- Agent 或分段请求初次失败后最多自动重试两次，只重试失败阶段；
- Agent 返回结构错误、越权证据或疑似内部信息泄漏，按对应阶段失败处理；
- WorkTool 明确返回可重试失败时最多自动重试两次，并重复发送同一份已固化内容；
- WorkTool 超时或网络中断导致无法确认发送结果时，不自动重发，进入“发送待确认”；
- “发送待确认”必须先通过可用回执查询，或由员工确认群里未收到，才能手工重试；
- 已确认发送成功的 occurrence 永不再次发送；
- 手工重试保留原执行记录并新增尝试记录，不能覆盖审计历史。

## 控制台体验

### 群管理任务卡

任务卡保持现有卡片加 icon 风格，并展示：

- 任务名称和任务类型；
- 启用开关；
- 周期、执行日和目标推送时间；
- 配置的 `@` 群角色；
- 距离目标推送时间的本地倒计时；
- 最近一次最终执行结果；
- 下一次目标推送时间；
- 记录、编辑和删除入口。

任务卡不显示实时达成状态，也不常驻显示提前分析说明。文字长度、角色数量和状态变化不能改变操作区位置；长内容省略并通过既有详情方式查看。

### 会话 Tab 群任务概览

群聊右上角继续使用与私聊资产按钮等宽的“任务 N”入口，但面板中的任务状态改为本文的执行状态和倒计时。私聊资产保持不变，群聊不显示资产。

点击任务可前往群管理的当前群与群任务 Tab。会话 Tab 不提供任务编辑，不引入私聊任务状态机。

### 执行详情

点击最近一次结果或“记录”打开 Dialog，至少展示：

- 计划目标时间、实际开始和完成时间、延迟时长；
- 条件推送的已达成/未达成结论与简短说明；
- 周期汇总的最终 Review；
- 实际发送内容和 `@` 对象；
- 证据消息列表；
- 技术失败阶段、错误摘要和各次重试；
- 发送待确认的处理说明和受控手工重试入口。

点击证据复用标签提醒的导航链路：即使目标群会话尚未加载，也要先加载并选中对应群，再加载消息附近历史、滚动并高亮目标消息。

### 不足 10 分钟的配置反馈

页面平时不展示说明文本。只有新建或修改任务后，下一目标时间不足 10 分钟时显示一次必要反馈：本次计划不会采用新配置，系统将选择下一次满足提前量的计划时间。

## 数据模型边界

继续保留并演进：

- 原始 `conversation_messages`；
- 群任务与执行日配置；
- 任务 `@` 角色关系；
- 任务配置版本或等价快照；
- occurrence 主记录与阶段状态；
- occurrence 临时分段、检查点和租约；
- 最终判断、最终内容、简短说明、证据消息关系；
- WorkTool 发送尝试、命令结果和人工操作审计。

删除且不再读取：

- 群事实及其类别、稳定语义键和结构化值；
- 事实证据账本、修订、更正、撤销和替代关系；
- 群事实聚合与累计投影；
- 账本任务、游标、状态、重建和回溯队列；
- 任务周期实时达成状态；
- `group-ledger` Agent purpose、提示、解析器和 Worker；
- 依赖持久事实或变量结果的旧汇总执行路径。

所有任务、执行、历史和证据查询必须同时限定 workspace、Bot 和稳定群 ID。群名只用于展示和当前 WorkTool 地址，不能作为权限或数据主键。

## 迁移与发布顺序

### 阶段一：DClaw 兼容能力

- 增加群历史无推理批量追加能力；
- 增加按 Bot、群、时间范围和游标读取能力；
- 增加稳定消息 ID 去重和受限授权；
- 保持现有即时回复接口兼容。

### 阶段二：历史回填与双写验证

- WorkTool 本地消息继续正常持久化；
- 新消息追加到 DClaw 群历史；
- 分批回填已有本地群消息；
- 比较数量、边界消息、参与者和时间顺序，确认目标群所需范围完整；
- 回填或验证失败时不启动新任务执行器。

### 阶段三：任务执行器切换

- 已有任务保留名称、类型、启用状态、周期、时间、条件、固定内容、模板和 `@` 角色；
- 下一次满足提前量的 occurrence 使用新历史分析路径；
- 停止实时条件判断、账本写入和账本回溯；
- 旧执行历史保留为只读，不伪装成新引擎结果。

### 阶段四：账本删除

- 删除账本服务、Worker、Agent purpose、路由依赖和控制台实时状态；
- 确认新路径稳定且无回滚依赖后，通过明确数据库迁移删除旧账本表；
- 删除前不得影响原始消息、任务配置、执行历史和证据定位；
- 数据库迁移必须可识别未完成回填或仍在运行的旧 Worker，并拒绝在不安全状态下继续。

发布顺序必须是 DClaw 先兼容、WorkTool 后切换。DClaw 历史能力未就绪时，WorkTool 不得用不完整上下文执行或发送群任务。

## 失败处理

- 历史缺段、越权、回填未完成：执行失败，不调用发送；
- Token 估算超过预算：进入分段路径，不直接提交超长提示；
- 某一分段失败：只重试该分段，超过次数则整个 occurrence 失败；
- 最终合并无效：重试最终合并，不重复处理成功分段；
- 条件未达成：正常“未发送”，不重试；
- 周期汇总数据稀少：生成克制 Review，不作为技术失败；
- WorkTool 明确失败：受控重试同一内容；
- WorkTool 结果不明确：发送待确认，不自动重发；
- 分析超过目标时间：继续执行并记录延迟，不能牺牲信息完整性；
- 服务重启：通过持久阶段、检查点、租约和唯一键恢复。

## 监控与审计

至少记录以下指标和结构化日志：

- 每个 occurrence 的历史消息数、估算 Token、分段数和覆盖时间范围；
- 预分析开始、目标时间、最终完成时间和延迟；
- 各阶段耗时、重试次数和模型调用量；
- DClaw 历史写入积压、回填游标和缺段校验；
- Agent 输出校验失败、越权证据和保密校验失败；
- WorkTool 明确失败、结果不明确和最终确认结果；
- 手工确认与重试操作者。

日志不得记录完整敏感群背景、角色说明、系统提示词或不必要的完整群聊正文。

## 测试策略

实施遵循 TDD，至少覆盖以下层次。

### DClaw 历史契约

- 无推理追加不会创建 Agent 回复；
- 稳定消息 ID 去重；
- 群改名不分裂历史；
- Bot、群和时间范围隔离；
- 分页完整且顺序稳定；
- 本地历史回填可中断恢复和重复执行。

### 时间与调度

- 北京时间日、周、月自然周期边界；
- 同周期多执行日使用重叠的周期截至口径；
- 1 日至 28 日和月底；
- `T-10 分钟` 预分析、`T` 增量补齐和 `T` 后消息排除；
- 不足 10 分钟的任务创建或编辑选择下一有效 occurrence；
- 配置版本在预分析开始后固定。

### 长上下文

- 紧凑逐行格式保留参与者、时间、来源、类型和消息映射；
- 分隔符、换行和非文本消息正确转义；
- 预算内单次执行与超预算分段路径；
- 所有分段覆盖连续且不重不漏；
- 单分段失败只重试失败分段；
- 多层合并不会超出模型上下文；
- 服务重启从检查点继续。

### 条件推送

- 达成时发送固定原文；
- 未达成时不调用 WorkTool；
- Agent 不能改写内容或增加 `@`；
- 达成证据必须属于当前群和时间范围；
- 最后 10 分钟的新消息可以改变最终结论；
- Bot 自己的消息不能单独证明客户动作。

### 周期汇总

- 模板被理解为自然结构和统计规则，而非持久变量；
- 完整周期历史可以生成统计和 Review；
- 模板明确要求累计时可以读取建群以来的历史，同时保持当前周期指标的范围不变；
- 数据少时如实输出且仍然生成；
- 不编造数字，不泄漏未解析模板语法；
- 核心统计证据可定位；
- 群背景、角色配置和内部机制不出现在发送内容中。

### 状态、恢复与发送

- 唯一 occurrence 防止多实例重复；
- 执行中租约、心跳和重启恢复；
- 同任务 occurrence 串行排队；
- 最终内容固化后发送重试不重新生成；
- 明确失败重试与不明确结果停止重试；
- 已发送、未发送、执行失败和发送待确认映射正确；
- 手工确认与重试保留完整审计。

### 控制台与回归

- 群管理任务卡不显示实时达成状态和常驻提前分析文案；
- 会话 Tab 群任务概览使用新状态，私聊资产完全不变；
- 执行记录和证据定位在会话未加载时仍可工作；
- 长名称、多角色、长状态和窄屏不破坏卡片布局；
- 群即时回复、知识库、MindSpace、智库、标签、私聊任务和推送 Tab 无回归。

## 验收标准

1. 所有新入站和出站群消息均完整、幂等地进入当前群的 DClaw 历史空间，且不会因写历史调用 Agent。
2. 本地已保存历史可以回填并按消息 ID 去重，任务能够分析功能上线前已保存的群消息。
3. 条件推送只在执行窗口判断，达成时发送固定原文，未达成时正常不发送。
4. 周期汇总不再依赖账本或预定义变量，能够按自然语言模板生成最终专业 Review。
5. 日、周、月任务默认读取当前自然周期开始至目标推送时刻的完整历史，同周期多次执行允许范围重叠；模板明确要求累计时可以读取建群以来至目标时刻的历史。
6. 系统提前 10 分钟分析旧历史，到点补齐最后 10 分钟消息，不漏掉临近执行的新证据。
7. 超长历史不会直接导致上下文溢出，分段处理覆盖完整授权范围并支持断点恢复。
8. 分段临时结果不成为长期群账本，旧事实、聚合、变量、游标和实时状态链路被删除。
9. 用户可以看到倒计时、执行中、已发送、未发送、执行失败和发送待确认，并能查看执行详情。
10. WorkTool 发送结果不明确时不会自动重复发送，已固化内容在任何发送重试中保持一致。
11. 群背景、角色配置、系统提示词、内部说明和历史读取机制不会出现在群消息中。
12. 点击执行证据可以加载正确群会话并定位、高亮原始消息。
13. 群任务与私聊任务状态机、资产、标签、群即时回复和现有推送能力保持隔离。
