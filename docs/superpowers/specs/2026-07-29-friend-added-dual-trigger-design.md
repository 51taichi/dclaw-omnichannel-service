# 新好友双触发识别修复设计

## 背景

当前新好友流程只把企微系统文本“我已经添加了你，现在我们可以开始聊天了”作为有效触发器。
WorkTool 的 `textType=22`、`type=105` 新增好友事件虽然会进入原始消息审计表，但业务处理会明确跳过。

当 WorkTool 没有把企微系统文本作为标准私聊文本回调时，新好友随后发送的第一条普通消息会被误判为老客户，
直接进入任务最后节点。2026-07-29 的“知行合一”和“易天缘”符合这一故障表现。

## 目标

- 同时支持企微系统欢迎语和 WorkTool `textType=22`、`type=105` 新增好友事件。
- 任一信号有效到达都能把客户识别为新客户，并进入任务入口节点。
- 同一次新增好友产生两个信号时，只执行一次流程重入和一次入口激活任务创建。
- 不把新增好友事件发送给 Agent，也不额外即时发送欢迎语。
- 保持现有老客户识别、会话重入和入口节点延迟激活行为。

## 非目标

- 不改变入口节点激活话术、间隔或发送次数。
- 不改变客户发送普通消息后取消待执行激活任务的行为。
- 不依赖 WorkTool 历史消息接口判断客户是否为新好友。
- 不修改群聊处理。

## 触发识别

新增好友信号分为两类：

1. `system_greeting`
   - 私聊，`roomType` 为 `2` 或 `4`。
   - `textType=1`。
   - 文本规范化后等于“我已经添加了你现在我们可以开始聊天了”。
2. `worktool_friend_event`
   - `textType=22`。
   - `type=105`。
   - `friendName` 非空。

`worktool_friend_event` 需要先规范化成私聊联系人消息：

- `roomType=2`
- `receivedName=friendName`
- 使用 `botId + friendName` 生成私聊 `conversationKey`
- 保留原始事件字段用于审计

两个信号都调用同一个新增好友业务处理函数，不复制流程状态变更逻辑。

## 去重与重入

新增一个独立的“信号去重窗口”，默认 30 秒：

- 同一 `botId + conversationKey` 在窗口内再次收到任一新增好友信号，视为同一次新增好友的重复信号。
- 重复信号只保留原始消息审计，不重置会话、不增加会话周期、不创建新的入口激活任务。
- 去重使用已有 `flow_sessions.last_friend_added_at` 持久时间，服务重启后仍有效。
- 去重窗口与 `FRIEND_ADDED_REENTRY_COOLDOWN_MINUTES` 分离。

`FRIEND_ADDED_REENTRY_COOLDOWN_MINUTES` 继续负责业务层面的重新添加冷却；即使该值为 `0`，30 秒信号去重仍然生效。
超过信号去重窗口后再次收到新增好友信号，继续按现有重新添加流程处理。

可通过 `FRIEND_ADDED_SIGNAL_DEDUPE_SECONDS` 调整信号去重窗口，合法值最小为 1 秒，默认 30 秒。

## 处理顺序

收到回调后按以下顺序处理：

1. 原始回调写入 `incoming_messages`。
2. 判断是否为系统欢迎语或 WorkTool 新增好友事件。
3. WorkTool 事件先规范化联系人姓名和私聊会话键。
4. 检查 30 秒信号去重窗口。
5. 非重复信号调用现有新增好友流程：
   - 建立或重置会话；
   - 标记为新客户；
   - 回到任务入口节点；
   - 应用添加日期标签；
   - 按入口节点配置创建延迟激活任务。
6. 结束该回调，不进入 Agent 普通消息合并队列。

客户随后立即发送普通消息时，仍由当前逻辑取消待执行入口激活，并直接让 Agent 回复客户当前问题。

## 日志

新增好友相关日志增加 `trigger`：

- `system_greeting`
- `worktool_friend_event`

信号窗口命中时记录：

- 事件：`friend_added.skipped`
- 原因：`friend_added_signal_duplicate`
- `trigger`
- `conversationKey`
- 距离上次有效新增好友信号的时间

这可以区分信号重复、业务冷却、缺少绑定和未配置入口激活。

## 测试

至少覆盖：

1. 标准系统欢迎语继续触发新好友流程。
2. `textType=22`、`type=105`、有效 `friendName` 能触发同一新好友流程。
3. 其他 `textType/type` 组合不能触发。
4. 缺少 `friendName` 的 WorkTool 事件不能创建会话。
5. WorkTool 事件先到、系统欢迎语后到，30 秒内只重入一次并只创建一个激活任务。
6. 系统欢迎语先到、WorkTool 事件后到，结果相同。
7. 信号去重不调用 Agent，不生成即时欢迎消息。
8. 超过信号去重窗口后仍可执行现有重新添加逻辑。
9. 普通私聊首次消息仍按现有老客户规则处理。
10. 全量测试通过。

## 发布验证

部署后新增一个测试客户，核对日志依次出现：

- `friend_added.received`
- `friend_added.activation.scheduled` 或入口未配置时的明确跳过原因
- 若两个信号均到达，第二个出现 `friend_added_signal_duplicate`

控制台应显示该客户位于任务入口节点，不显示“老客户”标识；入口激活任务最多一条。
