# 驾驶舱时间口径一致性设计

日期：2026-08-02
状态：已按用户确认的推荐方案进入实现

## 目标

驾驶舱的日报、周报、月报统一使用系统既定的 `Asia/Shanghai` 自然周期，避免服务运行环境的时区改变统计边界。修复指定日期查询无法命中历史 UTC 快照的问题，同时保持驾驶舱读取、聚合、AI 报告与核心回复链路隔离。

## 设计

- 在驾驶舱领域层定义唯一的系统时区常量，周期计算默认并固定使用 `Asia/Shanghai`。
- 驾驶舱配置归一化不再读取 Node 或容器的本地时区，旧配置读取后也归一为系统时区。
- 新统计快照只使用北京时间周期写入。
- 指定日期查询先匹配北京时间周期；若不存在，再匹配同一选择值对应的旧 UTC 周期。兼容仅发生在读取端，不迁移、不覆盖历史快照。
- 历史日报匹配使用与快照相同的候选周期，避免指标恢复而日报留档仍消失。
- 驾驶舱概览继续只读，不触发重算或 AI 调用。

## 验收

- 选择 2026-08-01 时，北京时间周期为 `2026-07-31T16:00:00.000Z` 至 `2026-08-01T16:00:00.000Z`。
- 北京时间快照缺失且旧 UTC 快照存在时，页面能够读取 `2026-08-01T00:00:00.000Z` 周期的数据与日报。
- 新聚合不再受服务器 `TZ` 或容器默认时区影响。
- 驾驶舱之外的消息、任务推进、标签判断和 Agent 回复代码不发生修改。
