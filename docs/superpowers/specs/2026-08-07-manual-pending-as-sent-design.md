# 人工消息 `pending` 显示为已发送设计

## 目标

Whapi 文本发送接口返回 `accepted: true` 且提供有效消息 ID 后，控制台立即将该人工消息显示为“✓ 已发送”，不再长期显示“发送中”。

## 语义

数据库继续保存 Whapi 原始状态，不改写 `pending`：

| Whapi 状态 | 控制台显示 |
| --- | --- |
| `pending` | ✓ 已发送 |
| `sent` | ✓ 已发送 |
| `delivered` | ✓✓ 已送达 |
| `read` | 蓝色 ✓✓ 已读 |
| `played` | 已播放 |
| `failed` | 发送失败 |

这里的“已发送”表示 Whapi 已接受发送请求，不表示对方设备已收到；“已送达”和“已读”仍只由 Whapi Webhook 回执确认。

## 范围

- 只修改人工消息状态的前端展示映射。
- 不修改数据库状态、Webhook 处理、刷新机制或发送接口。
- `accepted: false` 仍由服务端返回错误，不创建成功消息气泡。
- 不新增轮询、SSE 或 WebSocket。

## 测试与验收

- 先修改前端状态映射测试，要求 `pending` 输出 `✓ 已发送`，并确认当前实现按预期失败。
- 实现最小映射修改后，运行定向测试与完整测试套件。
- 人工发送接口成功后，刷新会话时 `pending` 显示“✓ 已发送”；后续回执仍可推进为“已送达”或“已读”。
