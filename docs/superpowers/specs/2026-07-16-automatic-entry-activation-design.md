# 入口节点自动激活设计

## 目标

让状态机配置只保留“启用客户激活”这一项，不再要求业务人员选择触发时机。

- 所有节点启用激活后，AI 成功回复客户会启动该节点的激活计时。
- 入口节点启用激活后，WorkTool 新增好友事件也会启动该节点的激活计时。
- 企业微信自行发送欢迎语或资料链接时，即使客户没有发文字消息，也能在设定时间后收到激活话术。

## 配置与兼容性

控制台移除“触发时机”选择。节点激活继续保留：启用开关、是否由 Agent 美化、
间隔、次数和话术。

历史状态机 JSON 中可能存在 `activation.trigger`。服务端在读取时忽略该字段，
不再以它决定调度行为；后续通过控制台保存时不再写入该字段。这样既不需要迁移
已有数据，也不会改变已有节点的激活参数。

## 调度规则

### 入口节点

入口节点开启激活且存在话术时，有两个独立的起点：

1. WorkTool 收到 `textType=22`、`type=105` 的新增好友事件后，以事件时间启动
   第一次激活计时。此路径仅建立会话和任务，不调用 DClaw，也不补发欢迎语。
2. 客户后续发来私聊消息后，服务端先取消新增好友任务；AI 回复成功后，按当时
   当前节点的激活配置重新启动计时。

### 后续节点

后续节点不会从新增好友事件启动。只要该节点开启激活，AI 在该节点成功回复后就会
启动计时。

### 单一有效任务组

同一私聊会话的每次触发都会先使旧激活任务失效，再创建当前这一轮的任务组。因此
新增好友计时和 AI 回复计时不会同时向同一客户发送话术。

客户回复、人工接手、清空会话、节点切换仍沿用现有取消机制，都会取消未执行任务。
若 AI 调用或发送失败，则不会创建新的 AI 回复激活任务。

## 实现边界

- 新增好友事件仍使用 `friendName` 生成既有私聊会话键。
- 群聊不参与状态机和新增好友激活。
- 不修改 DClaw Agent 文件或协议。
- 控制台不展示、也不再编辑 `activation.trigger`。

## 测试

- 入口节点开启激活时，新增好友事件能创建任务，无论历史 `trigger` 值是什么。
- 后续节点不会被新增好友事件调度。
- 所有启用激活的节点都可在 AI 成功回复后调度任务。
- 客户回复会取消新增好友任务，随后 AI 成功回复仅保留新的任务组。
- 控制台不再渲染“触发时机”字段，保存的节点激活配置不再包含 `trigger`。
