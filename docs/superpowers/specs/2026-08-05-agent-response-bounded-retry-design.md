# Agent 响应有限重试与空回复门禁设计

## 目标

提高实时客户消息的回复确定性，同时避免 Agent 持续返回错误 JSON 时形成无限循环、阻塞实时队列或产生不可控费用。

## 适用边界

- AI 控制中的实时私聊消息必须返回非空文字或至少一个可发送附件。
- 后台历史分析、标签分析、任务判断等非客户回复请求允许 `reply` 为空。
- 未获得回复授权的群消息允许静默；已获得回复授权的群消息继续要求非空回复。
- 本次不改变标签、资产、流程节点和 WorkTool 发送逻辑。

## Gateway 处理流程

每次 Agent 响应都先经过相同的 Gateway 校验流程：

1. 规范化响应文本并尝试确定性的本地 JSON 修复。
2. 校验 JSON 语法、响应结构、回复内容、流程决策、标签证据和附件可发送性。
3. 校验通过后才允许进入标签、资产、流程和发送等业务层。
4. 校验失败时，根据错误类型决定下一次请求方式，但总 Agent 调用次数不得超过 3 次。

### 重试策略

- JSON 语法错误且本地无法修复：使用与首次完全相同的原始请求重新生成，不携带错误 JSON。
- 结构或语义错误：沿用现有定向纠错请求，告诉 Agent 具体校验错误。
- 实时私聊的 `reply` 为空且没有可发送附件：按语义错误处理，不允许作为成功响应进入业务层。
- 每次新响应仍先执行本地修复；修复成功后立即停止重试。
- 最多调用 Agent 3 次，包括第一次正常调用。

## 最终失败

第三次响应仍未通过时：

1. 将每次失败的错误类型、错误位置、原始响应和尝试序号写入 `agent_response_validation_failures`。
2. 将最终重试结果明确记录为失败，不把无效响应写成成功调用。
3. 对实时私聊发送管理员配置的失败兜底话术。
4. 群消息和后台分析继续遵循各自现有的失败处理规则。

## 可观测性

- 每次失败保留独立记录，尝试序号为 1、2、3。
- 日志区分本地修复成功、重新生成成功、定向纠错成功、调用失败和最终失败。
- 最终失败记录必须能够关联 `invocation_id`、会话、客户消息和兜底发送结果。

## 测试范围

- 第一次返回正确 JSON，不发生额外调用。
- 第一次 JSON 可本地修复，不发生额外调用。
- 前两次 JSON 错误、第三次成功，共调用 3 次并正常发送。
- 三次均失败，停止继续调用并发送兜底话术。
- 实时私聊空 `reply` 被 Gateway 拦截。
- 后台分析空 `reply` 仍然允许。
- 回复只有可发送附件时视为有效。
- 标签、资产和流程决策只应用最终通过校验的响应。

## 非目标

- 不实现无限重试。
- 不修改 Agent 项目。
- 不增加新的控制台配置项。
- 不调整 DClaw 超时、并发队列或 WorkTool 回调逻辑。
