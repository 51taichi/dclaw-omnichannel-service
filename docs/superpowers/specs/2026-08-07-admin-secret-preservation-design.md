# 管理后台密钥保留设计

## 目标

管理员编辑并保存 Bot 或 Agent 配置时，未修改的密钥必须继续保留，不能被空字符串、掩码占位符或缺失字段覆盖。

本次范围包括：

- Whapi API Token
- Whapi Webhook Secret
- DClaw OpenAPI API Key

## 页面行为

编辑现有配置时，密钥输入框不回填真实明文，统一显示已配置状态或 `*****` 占位。占位符只代表“已有密钥”，绝不作为新密钥提交或保存。

用户不操作密钥输入框并保存其他字段时，前端省略对应密钥字段。用户明确输入新的非空密钥时，前端才提交该值以执行替换。

管理员密码和 Bot 登录密码继续采用独立的密码重置流程，不参与普通配置保存。

## 服务端更新语义

服务端是最终保护边界，不能依赖前端行为保证安全：

- 密钥字段缺失：保留数据库现值；
- 密钥字段为空字符串：保留数据库现值；
- 密钥字段等于掩码占位符：保留数据库现值；
- 密钥字段为新的非空值：验证后替换数据库现值。

上述规则同时应用于 Agent 独立编辑、Bot 编辑以及兼容旧请求的内联 Agent 创建/更新路径。

## 各密钥的存储规则

### OpenAPI API Key

继续按现有方式保存。更新 Agent 时，只有收到新的非空值才替换 `agents.agent_api_key`，否则沿用原值。

### Whapi API Token

继续采用 AES-256-GCM 加密保存。只有收到新的非空 Token 才重新加密并替换；未修改时沿用原密文。

### Webhook Secret

继续保存不可逆哈希。只有收到新的非空 Secret 时才生成新哈希并重新配置 Whapi Webhook；未修改时保留原哈希，不触发轮换。

Webhook Secret 无法从哈希恢复，因此页面只显示“已配置”，不会尝试回填明文。

## 接口与安全

管理员读取接口只返回密钥是否已配置以及必要的末尾提示，不返回完整明文。普通 Bot、工作区和公开 Webhook 接口维持现有权限边界。

密钥不得进入日志、错误响应、Webhook 事件记录或浏览器持久化存储。

## 测试

测试覆盖：

1. Agent 更新缺少、留空或提交掩码 API Key 时保留旧值。
2. Agent 明确提交新 API Key 时正确替换。
3. Bot 更新缺少、留空或提交掩码 Whapi Token 时保留旧密文。
4. Bot 更新缺少、留空或提交掩码 Webhook Secret 时保留旧哈希且不重新配置 Webhook。
5. 明确提交新 Token 或 Webhook Secret 时正确替换。
6. 管理员页面不回填真实密钥，且普通配置保存不提交占位符。
7. 管理员读取接口和其他接口均不泄露完整密钥。
