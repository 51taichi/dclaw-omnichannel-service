# 会话详情网络失败重试设计

## 背景

生产日志显示 Peptide 会话详情请求能够返回 HTTP 200，应用和代理均无 5xx 或重启，但浏览器偶发显示原生 `Failed to fetch`；刷新页面后相同会话恢复。该会话响应约 256 KB，属于一次性的客户端或 HTTP/2 传输中断，而非会话数据损坏。

## 行为

- 仅 `openFlowSession` 发起的会话详情 GET 请求启用网络重试。
- 第一次 `fetch` 在收到响应前抛出网络异常时，静默重试一次。
- HTTP 401、HTTP 500、服务端 `{ ok: false }` 和 JSON 协议错误不重试。
- 第二次网络请求仍失败时，沿用现有“会话记录加载失败”界面和错误上抛行为。
- 发送消息、人工切换、标签、删除、重置和上传等读写请求不使用该重试，避免重复操作。
- 重试期间保持现有加载态，不显示第一次失败提示。

## 实现边界

在控制台客户端增加一个专用于只读请求的轻量包装函数，例如 `requestWithNetworkRetry(path, options, { retries: 1 })`。它调用现有 `request`，只捕获浏览器网络异常；为便于准确区分，在 `request` 的原始 `fetch` 异常上标记 `isNetworkError=true` 后继续抛出。`openFlowSession` 使用该包装函数，其他调用保持不变。

## 验证

- 第一次网络失败、第二次成功：共请求两次并返回成功数据。
- 连续两次网络失败：共请求两次并抛出第二次异常。
- HTTP 500：只请求一次并立即抛错。
- 源码边界测试确认只有会话详情加载使用网络重试包装函数，所有写操作仍使用现有 `request`。
