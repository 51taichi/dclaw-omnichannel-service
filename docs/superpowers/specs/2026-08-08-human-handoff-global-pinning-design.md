# 人工接手会话全局置顶设计

## 问题

会话接口先按最近消息时间分页，浏览器随后只对当前页执行“人工接手优先”排序。客户经搜索进入当前页并切换成人工接手后，清空搜索会重新加载普通第一页；若该客户原本不在最近消息第一页，浏览器便无法看到它，也就无法将它置顶。

## 目标行为

- 人工接手会话在服务端查询结果中全局优先，而不是仅在浏览器当前页优先。
- 人工接手组内及 AI 会话组内继续按最后消息时间倒序排列，相同时按会话 ID 倒序稳定排列。
- 搜索、会话类型、节点、标签和日期过滤仍先限定候选集合；排序发生在分页之前。
- 切换人工接手不修改最后消息时间。
- 前端现有本页排序保留，作为即时更新与动画展示逻辑；其顺序须与服务端一致。

## 实现

修改 `listFlowSessionsPage` 的 SQL 排序：先按 `handoff_status = 'human'` 降序，再按 `last_message_at` 和 `id` 降序，最后执行 `LIMIT/OFFSET`。

不增加额外接口，不在前端合并另一份人工会话列表，也不把接手操作伪装成新消息活动。

## 验证

数据库回归测试构造超过一页的会话：目标客户按最近消息排序不在第一页，搜索能够找到它；切换人工后，清除搜索并读取第一页，目标客户必须位于第一条。测试同时验证其原最后消息时间未被改变，并验证 AI 会话仍按最近消息排序。
