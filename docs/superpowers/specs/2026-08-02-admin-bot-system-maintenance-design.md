# Bot 系统维护配置迁移设计

## 目标

- 中台配置页只保留面向运营人员的业务配置。
- 将“Bot 密钥”和“调试自动回复”迁移到管理后台的 Bots 页面。
- 继续使用现有 Bot 密钥与调试自动回复接口，不改变鉴权、消息处理或机器人回复逻辑。

## 信息架构

管理后台 Bots 页面分为两层：

1. Bot 基础信息：Bot ID、Bot 名称、绑定 Agent、启用状态。
2. 系统维护：Bot 密钥、调试自动回复。

系统维护区域只在管理员选择一个已保存的 Bot 后显示。新建 Bot 时先保存基础信息，保存成功并进入编辑状态后才能维护密钥和调试配置。

## 系统维护区域

### Bot 密钥

- 提供一个新密钥输入框和独立的“修改密钥”按钮。
- 输入框默认留空，不读取或回显已有密钥。
- 提交时复用 `PUT /api/bots/:botId/access-key`。
- 修改成功后清空输入框并显示顶部提示。

### 调试自动回复

- 提供启用开关、触发词和回复内容。
- 选择 Bot 时通过 `GET /api/bots/:botId/settings/debug-reply` 加载当前配置。
- 通过 `PUT /api/bots/:botId/settings/debug-reply` 独立保存。
- 切换 Bot 时立即清空上一 Bot 的系统维护内容，加载完成前禁用操作，避免短暂显示旧数据。

## 中台调整

- 从配置页移除可见的“Bot 密钥”和“调试自动回复”模块。
- 移除中台对这两块表单的加载、保存和事件绑定。
- 其他业务配置、Bot 解锁、会话和消息处理流程保持不变。

## 权限与接口

- 管理后台继续使用 `x-admin-session-token`。
- 现有两个 Bot 级接口已接受管理员会话，不新增接口，也不修改服务端权限规则。
- 迁移不会改变调试自动回复在服务端的触发顺序、匹配逻辑或实际回复行为。

## 异常处理

- 未选择已保存 Bot 时隐藏系统维护区域。
- 配置加载失败时保持区域不可编辑并显示顶部错误提示。
- 保存期间禁用对应按钮，防止重复提交。
- 切换 Bot 后忽略上一 Bot 尚未返回的异步结果。

## 验证

- 边界测试确认中台不再包含两个配置模块及相关客户端逻辑。
- 管理后台测试确认系统维护区域、图标、开关和独立保存操作存在。
- 测试管理员会话可继续调用现有两个接口。
- 运行完整测试套件，确认消息处理和回复逻辑没有回归。
