# 驾驶舱密度与首次数据设计

## 目标

在不改变单 Bot 统计、凌晨流水线和核心回复链路的前提下，提高驾驶舱首屏信息密度，并让首次部署后立即拥有昨天的统计快照。

## 页面

- 删除独立的“AI 经营结论”卡片。
- 在“完整统计”文字后放置现有样式的 help icon；悬停、键盘聚焦时显示“完整报告将在凌晨统计后生成”。
- 指标卡使用单行横向布局：图标和名称靠左，数字靠右；桌面端仍为四列，移动端逐级降列。
- 固定内容顺序：工具栏、指标、任务与标签图表、主要问题与建议行动、报告留档。
- 驾驶舱容器高度随视口变化，内容区独立纵向滚动，不再把整页无限撑高。
- 数据延迟、加载失败、保存结果等状态统一使用共享顶部 Toast。

## 首次数据

- 服务启动后只检查启用且完全没有日报快照的 Bot。
- 对这些 Bot 以当前时间为统计截点补建昨天的日报、周报和月报快照。
- 已存在任意日报快照的 Bot 不触发补建；进入驾驶舱仍然只读取快照。
- 初始化失败只记录日志，不阻塞服务启动或消息回复。

## 验证

- 静态边界测试验证 DOM 顺序、help icon、紧凑卡片和滚动 CSS。
- 单元测试验证初始化仅处理缺失快照的 Bot，且单 Bot 失败不会中断其他 Bot。
- 运行全量测试与服务健康检查。
